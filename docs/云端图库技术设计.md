# 羽栖 Key-only 云端图库技术设计

- 版本：1.0
- 日期：2026-11-05
- 状态：设计稿
- 关联文档：[云端图库开发规划](云端图库开发规划.md)
- 当前桌面版本：0.2.0
- 当前测试：250 项通过

## 1. 设计结论

不建设后端和账户系统，桌面端和手机端直接通过腾讯云 COS SDK 访问同一个私有桶。

```text
桌面分类：懂鸟 API Key
桌面图库：COS 配置
手机浏览：COS 只读 Key
```

`prefix` 只是对象命名空间：

```text
users/<prefix>/...
```

它不是认证，也不是授权边界。安全由 COS 子账号、桶策略和系统 Keychain 负责。

## 2. 组件

```text
macOS App
  ├── 本地图库 .birdroost
  ├── M0 cloud_export
  ├── M1 cloud_backup
  ├── cloud restore（待做）
  └── COS SDK

手机 App
  ├── COS SDK / 签名请求
  ├── manifest + taxonomy
  ├── 缩略图缓存
  └── Photos / MediaStore

腾讯云 COS
  ├── manifest.json
  ├── originals/
  ├── thumbs/
  └── taxonomy/
```

没有 API 服务、数据库服务、队列服务。

## 3. 对象布局

```text
users/<prefix>/manifest.json
users/<prefix>/originals/<sha256>.<ext>
users/<prefix>/thumbs/<sha256>_256.webp
users/<prefix>/thumbs/<sha256>_512.webp
users/<prefix>/taxonomy/<version>.json
```

规则：

- 全部私有
- 原图内容寻址
- 多物种副本共享同一原图
- 对象 key 不含地点、物种、日期等隐私信息
- 不依赖 ListObjects 做业务目录
- 手机端只需要 manifest 和已知 key

### revision 规则

- 每次 manifest 内容变化，`revision += 1`
- `device_id` 写最后修改设备
- 上传前读取远端 manifest
- 如果远端 `revision >` 本地已知 revision：
  - 停止自动上传
  - 提示“云端已被其它设备更新”
  - 用户选择重新拉取或强制覆盖
- 不做自动合并，第一版采用显式冲突提示

## 5. 本地状态

本地仍以 `.birdroost/groups/*.json` 为业务真相。

建议增加本地同步表：

```text
cloud_state
  prefix
  library_id
  remote_revision
  last_synced_at
  dirty

cloud_dirty
  entity_type
  entity_id
  changed_at
```

### dirty 触发

- group 写入
- 观测信息修改
- 纠错
- 删除
- copy 路径变化
- 手动点击上传

### 上传流程

```text
本地 dirty
→ 生成/更新 manifest
→ 读取远端 revision
→ revision 相同或本地为空
→ 上传新对象
→ 上传 manifest
→ 记录 remote_revision
```

## 6. 增量导出（M1.1 已实现基础版）

批次完成后主窗口会检测该 batch 的 groups/copies，询问是否上传。

当前增量策略：

- 扫描 manifest 时按 SHA-256 继续全量识别
- 已存在的 256/512 缩略图直接复用，不重新编码
- 上传计划仍列出全部对象，但 COS HEAD 大小一致时跳过
- 只对新增原图/新增缩略图产生真实上传
- Secret 仍由 UI/环境变量提供，不写入设置

## 6.1 原增量导出设计

当前 M0 `export_archive` 会扫描全库并重新生成缩略图。M1.1 需要改为：

- 对每个 copy 计算 SHA-256
- 在 manifest/缓存中查已有 photo
- 已存在 photo 跳过原图
- 缩略图文件存在则跳过
- 只处理新增/缺失
- manifest 仍全量生成，但体积可控

优化后续：

- 缩略图按 SHA 缓存
- manifest 使用 gzip
- 只导出 dirty group 的元数据，再合并旧 manifest

第一版为了简单，可以保留全量 manifest 生成；只优化原图和缩略图的上传。

## 7. 自动上传

批次完成后：

1. `ClassificationService` 完成
2. 主窗口获取本批新增 group_id
3. 弹窗：

```text
本批新增 23 张照片、约 180 MB。
是否立即上传到云端？
[上传] [稍后]
```

4. 用户确认后启动 `CloudBackupDialog` 或后台增量任务
5. 上传完成显示结果

注意：

- 不做“静默全量上传”
- 不阻塞主界面
- 失败可重试
- 用户可以关闭自动提示设置

## 8. 新电脑完整恢复

### 流程

```text
输入 COS 配置
→ 读取 users/<prefix>/manifest.json
→ 校验 schema_version
→ 选择完整下载
→ 下载 originals + thumbs
→ 校验 SHA-256
→ 重建 .birdroost/groups
→ 刷新 SQLite
→ 浏览
```

### 重建 `.birdroost`

从 manifest 的 groups/copies/observation/targets 生成：

```text
.birdroost/groups/<group_id>.json
```

图片路径：

```text
<local_root>/<species_cn>/<local_relative_path 的 basename>
```

如果 `local_relative_path` 与目标路径冲突：

- 使用 `species_cn + sequence` 重新生成
- 以 `copy_id` 为稳定标识
- 不覆盖已有不同内容文件

### 校验

- 下载后 SHA-256 必须与 manifest 一致
- 缩略图文件存在且尺寸正确
- group/copy 数一致
- 抽样打开原图

### 断点续传

- 已存在且哈希一致的文件跳过
- 下载临时文件 `.part`
- 完成后原子 rename
- 失败记录清单

## 9. 纠错/删除同步

### 纠错

- group 更新后标记 dirty
- 重新生成 manifest
- 上传 manifest
- 原图/缩略图不变，不重传

### 删除

- 不立即删除 COS 原图
- 在 manifest 写 tombstone
- 手机/其他 PC 隐藏
- 经过保留期后再清理对象

原因：

- 防止误删不可恢复
- 防止另一台设备重新上传“复活”
- 为多设备冲突留出恢复窗口

## 10. 手机端设计

### 目标

只读浏览，不写回云端。

### 技术路线

- iOS：Swift + 腾讯云 COS SDK + Photos framework
- Android：Kotlin + COS SDK + MediaStore
- 若想一套代码：Flutter + COS 签名请求 + 相册插件

第一版建议只做 iOS 或 Android 其中一个，不要同时做。

### 启动流程

```text
填写 Bucket / Region / Endpoint / Prefix / 只读 Secret
→ 保存到 Keychain/Keystore
→ 下载 manifest
→ 下载 taxonomy
→ 下载 256/512 缩略图
→ 显示分类树/物种列表
```

### 浏览流程

```text
列表：缩略图 + 物种 + 地点 + 时间
点开：512 缩略图 + 元数据
下载原图：COS GetObject
保存相册：Photos / MediaStore
```

### 手机缓存

```text
manifest：本地文件
taxonomy：本地文件
thumb_256：LRU 磁盘缓存
thumb_512：LRU 磁盘缓存
原图：用户主动下载后保存到相册，不长期缓存
```

### 手机安全

- 使用只读子账号
- 只授予 GetObject/HeadObject
- 不授予 Put/Delete
- Key 存 Keychain/Keystore
- 不写日志
- 丢失设备时通过 COS 轮换 Key

## 13. 安全设计

- COS 私有桶
- 手机只读子账号
- 桌面写账号与手机读账号分离
- Secret 存系统 Keychain
- 不上传 API Key 到 COS
- manifest 不含精确 GPS（当前只有地点文本）
- 分享图片前提示地点隐私
- 日志不输出 Secret、签名 URL
- 删除使用 tombstone

## 14. 成本

- 原图存储
- 缩略图存储
- 上传请求
- 手机下载流量
- 多设备重复下载

优化：

- 内容去重
- 缩略图优先
- 上传跳过已存在
- 手机缓存
- 生命周期策略
- 预算告警

## 14.1 COS 连接测试

云备份窗口提供“测试连接”按钮：

- 检查 bucket/region/Endpoint 和凭证
- `HeadBucket` 检查桶访问
- `HeadObject users/<prefix>/manifest.json` 检查目录
- 可选写入测试：创建并立即删除 `users/<prefix>/.birdroost-connection-test`
- 只读 Key 可以取消“包含写入测试”，只验证读取
- Secret 不写入日志或设置

## 15. 第一版实现顺序

```text
1. manifest v2 + 本地 dirty 状态
2. 增量导出/上传
3. 批次完成自动询问
4. 新电脑完整恢复
5. 纠错/删除写 tombstone + manifest 上传
6. 手机只读 App
```

不要先做账户系统和后端。
