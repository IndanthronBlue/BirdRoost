- 版本：0.1
- 日期：2026-11-05
- 状态：设计稿，未开始实现

## 1. 架构概览

```text
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│ Mac 客户端   │      │ Web/PWA      │      │ 手机客户端   │
└──────┬───────┘      └──────┬───────┘      └──────┬───────┘
       │                     │                     │
       └──────────────┬──────┴──────────────┬──────┘
                      │ HTTPS/JSON          │
                ┌─────▼─────────────────────▼─────┐
                │ API/BFF                          │
                │ 登录、权限、同步、签名 URL       │
                └─────┬───────────────┬────────────┘
                      │               │
              ┌───────▼──────┐  ┌─────▼──────────┐
              │ 云数据库      │  │ 腾讯云 COS      │
              │ 元数据/变更   │  │ 原图/缩略图     │
              └──────────────┘  └────────────────┘
                      │
              ┌───────▼──────┐
              │ 任务队列/函数 │
              │ 缩略图/校验   │
              └──────────────┘
```

原则：

- 客户端不持有 COS 永久密钥
- COS 桶默认私有
- 元数据在数据库，不在 COS 文件名里
- 原图按内容哈希存储
- 缩略图是可重建的派生数据

## 2. 组件选型（待定）

### 推荐

- 对象存储：腾讯云 COS
- 图片处理：COS 数据万象或客户端生成
- 账户：腾讯云 CloudBase Auth / 微信 / Apple / 手机号验证码
- API：FastAPI（Python）或 Go，部署在云函数/容器
- 数据库：PostgreSQL 或 MySQL
- 队列：Redis / 云消息队列
- CDN：可选，第一版可用 COS 签名 URL

### 不推荐

- 把 COS 当数据库
- 客户端内置 SecretId/SecretKey
- 自建明文密码表
- 用文件名做主键
- 用目录结构表达权限

## 4. COS 对象布局

```text
users/{user_id}/originals/{sha256}.{ext}
users/{user_id}/thumbs/{sha256}_512.webp
users/{user_id}/thumbs/{sha256}_256.webp
users/{user_id}/annotated/{sha256}.webp
users/{user_id}/exports/{timestamp}/manifest.json
```

要求：

- 全部私有
- 服务端加密
- 对象 key 不含鸟种、地点、日期等隐私信息
- 对象内容与 key 中的 sha256 一致
- 上传后做 HEAD/校验和验证
- 不依赖 ListObjects 做业务查询

## 5. 缩略图

建议尺寸：

| 用途 | 尺寸 | 格式 |
|---|---|---|
| 列表 | 256px 长边 | WebP |
| 详情 | 512px 长边 | WebP |
| 手机 | 512px 长边 | WebP |
| 原图 | 原尺寸 | 原格式 |

规则：

- 先按 EXIF orientation 矫正
- 不绘制检测框
- 带框图单独变体
- 保留宽高和 bytes 元数据
- 生成失败时记录 job，不影响原图上传
- 允许后台重建

## 6. 账户与权限

### 登录方式优先级

1. 邮箱/手机号验证码
2. Apple 登录
3. 微信登录
4. 密码登录只作为补充，不自建明文密码

### 授权模型

- 登录成功 → 短期 access token + refresh token
- API 校验 token → 得到 `user_id`
- COS 访问使用 STS 临时凭证或后端签名 URL
- STS policy 限制到：

```text
users/{user_id}/*
```

- 签名 URL TTL 建议 5～15 分钟
- 上传和下载都走同一套权限检查
- 任何跨用户读取都必须返回 403，不泄露对象是否存在

### 数据隔离

- 所有表带 `owner_id`
- 所有对象 key 带 `users/{user_id}/`
- 所有查询强制 owner 条件
- 管理员后台单独审计，不通过客户端接口

## 8. 同步协议

### 本地状态

本地 SQLite 增加：

```text
remote_id
remote_revision
sync_cursor
sync_state     clean/pending/conflict
last_synced_at
local_updated_at
```

### 拉取

1. 带 `cursor` 请求变更
2. 按 `seq` 应用变更
3. 更新本地 revision
4. 更新 cursor
5. 遇到本地 pending 的同实体，进入冲突检查

### 推送

1. 先拉取，避免基于旧 revision 修改
2. 每个实体带 `base_revision`
3. 服务端比较 revision
4. 成功返回新 revision
5. 冲突返回 409 + 服务端版本
6. 客户端展示冲突，不静默覆盖

### 冲突策略

第一阶段只读时不需要冲突处理。

双向同步时建议：

- 观测地、时间、备注：字段级最后写入优先
- 物种/目标：保留两版，提示用户选择
- 删除：tombstone 优先，但不物理删除原图
- 所有纠错记录不可变，只追加

## 9. 客户端缓存与按需下载

### 缓存层级

```text
内存缓存：当前屏幕缩略图
磁盘缓存：最近浏览缩略图
离线固定：用户主动下载的原图
```

### 下载策略

- 首屏：只拉元数据 + 256px 缩略图
- 详情：512px 缩略图
- 点击大图/下载：签名 URL 拉原图
- 支持 Range 和断点续传
- 下载后校验 sha256
- 缓存淘汰使用 LRU，用户 pin 的除外

### 手机端

第一版建议 PWA：

- 登录
- 按物种/地点/年份浏览
- 缩略图列表
- 点开大图
- 按需下载

不建议第一版在手机做批量上传、复杂纠错和完整图库管理。

## 10. 从本地迁移

1. 读取 `.birdroost/groups/*.json`
2. 为每个 copy 定位原图并计算 sha256
3. 相同 sha256 聚合为一个 photo
4. 上传原图一次
5. 建立 group/target/copy 元数据
6. 生成缩略图
7. 写入 change log
8. 校验 copy 数、唯一原图数、抽样哈希
9. 本地保留，不立即切换

迁移工具必须支持：

- dry-run
- 断点续传
- 失败清单
- 只重试失败项
- 不删除本地文件

## 11. 安全与隐私

- COS 私有桶，禁止公共读
- 服务端加密
- 全部 HTTPS
- 签名 URL 短 TTL
- 日志不打印 API Key、签名 URL、精确坐标
- 账户注销时删除对象或进入保留期
- 支持数据导出
- 鸟点位置默认不公开
- 分享卡片默认隐藏精确坐标
- 懂鸟 API Key 只保存在 Keychain 或服务端加密字段
- 不在 COS 对象 key 中出现地点/物种

## 12. 可观测性

需要记录：

- 上传成功率/失败原因
- 下载成功率/延迟
- 缩略图生成队列长度
- 同步冲突数量
- 每用户存储量
- COS 请求量/流量
- 账户异常登录

日志中禁止出现：

- API Key
- 完整签名 URL
- 精确 GPS/鸟点坐标

## 15. M0 导出实现

当前已加入 `birdclass.cloud_export`：

```bash
PYTHONPATH=src .venv/bin/python -m birdclass.cloud_export \
  --archive /path/to/鸟 \
  --output /path/to/鸟-cloud-export
```

输出结构：

```text
manifest.json
thumbs/{sha256}_256.webp
thumbs/{sha256}_512.webp
originals/            # M0 留空，M1 上传时再填充/引用源文件
```

manifest 顶层：

```json
{
  "schema_version": 1,
  "generated_at": "...",
  "source_root": "/path/to/鸟",
  "thumbnail_sizes": [256, 512],
  "counts": {"photos": 1241, "groups": 1140, "copies": 1252, "thumbnails": 2482, "errors": 13},
  "photos": [],
  "groups": [],
  "copies": [],
  "errors": []
}
```

`photos` 按 SHA-256 去重；`copies` 保留每个物种副本和 group 关联，因此不会为同一张原图重复上传 bytes。

M0 不触碰网络，也不修改 `.birdroost`。

## 15.1 M0.1 失效记录清理

本地导出前先清理失效 copy：

```bash
PYTHONPATH=src .venv/bin/python -m birdclass.archive_cleanup \
  --archive /path/to/鸟 --dry-run
```

规则：

- copy 文件不存在且路径在归档根目录内 → 从 group 移除
- 移除后 group 没有 copy → 整个 group JSON 移到 `.birdroost/quarantine/groups/<timestamp>/`
- 原本就没有 copy 的空 group → 同样隔离
- group 仍有有效 copy → 写回 group，保留
- 写 correction 记录，包含移除路径和是否隔离
- dry-run 只统计，不修改文件

## 15.2 M1 COS 上传实现

已加入：

```text
src/birdclass/cloud_backup.py
src/birdclass/ui/cloud_backup_dialog.py
```

UI 字段：

```text
导出目录
桶名（含 APPID）
地域
Endpoint（可选）
用户前缀
SecretId
SecretKey（掩码）
```

对象布局：

```text
users/<prefix>/originals/<sha256>.<ext>
users/<prefix>/thumbs/<sha256>_256.webp
users/<prefix>/thumbs/<sha256>_512.webp
users/<prefix>/manifest.json
```

安全约束：

- Secret 不写入 QSettings、manifest 或日志
- 留空时读取 `TENCENTCLOUD_SECRET_ID` / `TENCENTCLOUD_SECRET_KEY`
- 桶必须私有
- 当前不做账户认证，前缀只是一个用户标签，不能作为权限边界
- 正式多用户必须加后端 STS/签名 URL，不能把长期密钥放进客户端

### M1 UI 使用

主窗口“图片目录”区域 → “云备份…”：

```text
导出目录
桶名（含 APPID）
地域
Endpoint（可选）
用户前缀
SecretId
SecretKey（掩码）
[生成清单和缩略图] [开始上传] [取消]
```

用户前缀会映射为 `users/<prefix>/`。SecretId/SecretKey 不写入 QSettings；留空时从环境变量读取。

## 16. 第一版建议范围

如果只做第一版，建议严格限制为：

```text
单用户
上传原图 + 缩略图
云端目录
按需下载
不做账户
不做双向同步
不做手机编辑
```

先验证：

- 上传可靠性
- 缩略图体验
- 原图按需下载速度
- 真实存储和流量成本

验证通过后，再进入账户和只读多端阶段。
