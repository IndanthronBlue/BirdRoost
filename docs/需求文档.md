# 羽栖 BirdRoost 鸟图整理软件需求文档

- 文档版本：v1.13（归档浏览与纠错版）
- 编写日期：2026-10-25
- 目标平台：macOS（当前验证环境），其他桌面系统待验证
- 交付形态：Python 3.11 / 3.12 源码，通过 Python 解释器启动
- 项目目录：仓库根目录
- 本文范围：仅定义需求、行为与验收标准，不包含实现代码

## 1. 背景与目标

用户积累了大量鸟类图片，希望借助懂鸟 API 自动识别物种，并将图片复制到以物种中文名命名的目录中。软件需要控制 API 额度消耗，并支持额度不足后分多次继续处理同一批图片，避免重复识别。

### 1.1 核心目标

1. 用户通过图形界面配置 Key、识别类别、地区、观测地点、观测时间、源目录和目标目录。
2. 自动查询并显示图像识别剩余次数。
3. 自动遍历 JPG / JPEG / PNG 图片，调用懂鸟 API 识别。
4. 原图超过 2 MB 时生成临时压缩图用于上传，识别结束后清理临时文件，归档仍保留原图像素。
5. 按检测框独立识别和复核；同图不同鸟种分别复制到 `目标目录/物种中文名/观测地点_观测时间_物种中文名_编号.扩展名`，同种跨框只复制一次。
6. 原图写入全部鸟种中文名，复制件写入所属鸟种，并在写入后更新 CSV 文件身份。
7. 每个检测框最高候选置信度偏低或前两名近似并列时，逐框展示高亮原图、当前框候选和置信度，由用户手动选择。
8. 额度不足时安全停止，不提交超出本次可用额度的图片；多鸟复制不额外消耗额度。
9. 在源目录维护 CSV v3 记录并兼容 v1/v2，下次启动跳过已完成图片，恢复逐框复核或部分复制任务。
10. 在已安装依赖的 Python 3.11 虚拟环境中通过 `python -m birdclass` 启动。
11. 人工复核时允许跳过 API 候选，直接输入鸟种中文名，并按既有的命名、元数据、CSV 与断点续跑规则归档。

### 1.2 非目标（当前阶段不做）

- 不识别音频、视频、RAW、WebP、GIF、BMP、HEIC。
- 除写入鸟种中文名元数据外，不修改原图内容，不做旋转、裁剪、去重或画质增强；仅超限图片的临时上传副本会压缩。
- 不提供独立于人工复核弹窗的图库预览、图片编辑或批量手动改分类。
- 不批量并发上传；当前单线程顺序处理。
- 不移动或删除源图片，只复制。
- 不将未识别图片复制到“未知”目录。
- 不提供自动更新、安装向导、多用户、账号体系或云端数据库。
- 当前不考虑 PyInstaller、EXE、安装包、代码签名或免 Python 环境运行。

## 2. 可行性评估

### 2.1 技术可行性

懂鸟开放平台提供图片上传、异步结果查询和额度查询接口，可覆盖核心流程。Python 的桌面 UI、HTTP、文件与 CSV 生态成熟，使用 Python 3.11 虚拟环境即可开发和运行，因此当前方案可行。

识别不是同步接口：上传成功只代表任务受理，软件必须保存 `resultid` 并轮询结果，不能把上传成功直接当成分类成功。

### 2.2 主要约束

| 约束 | 对软件的影响 |
|---|---|
| 上传图片不超过 2 MB | 原图超限先生成不超过 2,000,000 字节的临时 JPEG，仅上传临时图；失败则不上传 |
| 上传图片每条边为 11～8192 像素 | 原图低于 11 像素时拒绝；超过 8192 像素时只在临时上传副本中等比缩小，归档仍用原图 |
| 上传后需轮询 | 按可配置总等待时长查询，默认 60 秒、范围 1～600 秒；处理中最多等待 1 秒再查，到期记为失败并继续下一张 |
| 图像额度有限 | 开始处理前查询额度，本次最多受理剩余额度数量的新图片 |
| `total=-1` 表示无限额度 | UI 显示“无限”，不设置图片数量上限 |
| 配额查询限 60 次/分钟 | 不为每张图片单独查询额度，批次开始和结束时查询 |
| 结果可能含多个动物目标、每个目标多个候选 | 需要明确统一的候选选择规则 |
| API 返回的是预测结果 | 软件只能保证按接口结果归档，不保证生物学识别绝对正确 |

### 2.3 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Key 泄露 | 额度被他人使用 | 密码掩码输入；日志脱敏；v1 默认不持久化 Key |
| 网络中断或程序崩溃 | 可能重复上传、重复扣费 | CSV 记录识别结果；已识别未复制者直接续拷；上传请求不做盲目自动重试 |
| 输出目录位于源目录内 | 下次扫描可能重复处理已复制图片 | 扫描时排除整个目标目录树及 CSV 自身 |
| 同名图片 | 相互覆盖 | 内容比较及冲突后缀，绝不静默覆盖不同内容 |
| 物种名含 Windows 非法字符 | 建目录失败 | 目录名清洗、保留名称映射并记录实际路径 |
| CSV 损坏或被手工改坏 | 无法可靠续跑 | 启动时校验表头与记录；损坏时停止并提示备份，不自动清空 |
| 多设备同时使用同一 Key | 本地额度快照过时 | 控制单批提交量；遇到额度类错误立即停止并重新查询 |
| Python 或依赖环境不一致 | 启动失败或行为差异 | 固定 Python 3.11 和依赖版本，使用独立虚拟环境并记录启动命令 |

## 3. 用户与使用场景

### 3.1 目标用户

拥有本地鸟类图片、已获得懂鸟 API Key，并希望在 Windows 上自动整理图片的个人用户。

### 3.2 典型场景

1. 用户输入 API Key，点击“查询剩余次数”，看到图像可用次数。
2. 用户选择“鸟（B）”、国家/地区、源目录和目标目录。
3. 软件校验输入、读取 CSV、扫描图片、排除已完成记录。
4. 若待处理数大于剩余额度，仅处理本次额度允许的数量，然后明确停止。
5. 每张图片识别成功后复制到物种目录，写入 CSV，更新进度。
6. 下次对同一源目录再次运行时，已完成图片跳过；已识别未复制图片不重新调用识别 API。
7. 上次失败或超过额度的图片仍可继续处理。

## 4. 术语与默认决策

| 术语 | 定义 |
|---|---|
| 源目录 | 用户输入的待分类图片根目录 |
| 目标目录 | 分类后图片的根目录 |
| 完成 | 识别成功、复制成功且 CSV 已完成状态落盘 |
| 已识别 | API 已返回有效物种，结果已记录，但复制可能尚未完成 |
| 失败 | 校验、上传、轮询、解析或复制未成功；不等于完成 |
| 待处理 | 未找到匹配完成记录，且不是可直接恢复复核或续拷的记录 |
| 待人工复核 | API 候选及复核原因已保存，等待用户确认、暂不分类或停止 |
| 文件身份 | 源目录内相对路径 + 文件大小 + 修改时间（纳秒） |
| 本次额度 | 批次开始时图像 `remaining`，`total=-1` 时视为无限 |

默认规则：递归扫描、扩展名不区分大小写、默认鸟类 `B`、默认全球 `WORLD`。仅当最高置信度不低于 80%，且唯一候选或与第二名差值大于 10 个百分点时自动取第一名；其余情况人工复核。

## 5. 功能需求

### 5.1 UI 与配置

**FR-UI-001：主界面字段**

主界面至少包含：

- API Key：密码掩码文本框，提供显示/隐藏切换。
- “查询剩余次数”按钮。
- 剩余次数显示区：未查询时显示“未查询”；结果显示图像剩余次数、总额度和已用次数。
- 识别种类下拉框：鸟（B，默认）、兽（M）、两栖（A）、爬行（R）。v1 不支持组合类别与尚未开放识别的 F。
- 国家/地区可搜索下拉框：显示“中文名（代码）”，默认“全球（WORLD）”；地区代码来自懂鸟附录快照。
- 观测地点、观测时间：两个必填文本框，用于复制件命名；观测时间允许自由文本，不自动以当前时间代替。
- 人工复核参数：“最高置信度低于”百分数输入框，默认 80%；“前两名置信度差不超过”百分点输入框，默认 10 个百分点。合法范围均为 0～100。
- 结果等待时长：整数秒输入框，默认 60 秒，范围 1～600 秒，表示上传后等待识别结果的总时长。
- 源目录文本框及“浏览…”按钮。
- 目标目录文本框及“浏览…”按钮。
- “开始分类”与“停止”按钮。
- 进度区：总数、已完成、本次成功、本次失败、已跳过、本次人工复核数、当前文件。
- 运行日志区：显示重要状态与错误，但绝不显示完整 Key。

**FR-UI-002：状态约束**

- 未开始处理时可编辑全部配置。
- 查询额度或分类期间避免重复提交同一操作。
- 分类运行时禁用 Key、类别、地区、观测地点、观测时间、阈值、结果等待时长、路径和开始按钮，仅保留停止按钮。
- 所有网络任务在后台执行，UI 不冻结。
- 停止表示不再受理新图片；当前已经上传的图片允许完成结果查询和归档，随后安全停止。
- 人工复核弹窗显示时，后台等待用户决定，不处理下一张、不继续上传；用户可在弹窗中确认选择、仅推迟当前检测目标或停止整批。

**FR-UI-003：配置保存**

- 保存识别类别、地区、观测地点、观测时间、两个人工复核阈值、结果等待时长、源目录、目标目录等非敏感设置。
- v1 默认不将 API Key 写入文件、注册表或日志；程序重启后需重新输入。

**FR-UI-004：系统外观适配**

- 主窗口、设置分组、输入框、下拉框及弹出列表、日志和人工复核候选区必须跟随系统浅色／深色外观，不得写死会破坏系统深色模式的浅色背景或前景色。
- 应用启动时使用当前系统外观；运行期间系统外观变化时自动刷新，无需重启。
- 两种外观下文字、占位提示、按钮和候选置信度均应清晰可读；图片预览底板和检测框颜色可保持固定，但不得影响候选及操作按钮的可读性。
- 不提供独立主题设置项，不将主题选择保存到 QSettings。

### 5.2 额度查询

**FR-QUOTA-001**

点击“查询剩余次数”后，通过 `POST /api/v2/dongniao`、Header `api_key`、表单 `quota=1` 查询并显示图像额度。该操作不消耗图像识别额度。

**FR-QUOTA-002**

- `total=-1` 时显示“总额度：无限；剩余：无限”。
- 普通额度显示接口返回的 `used / total / remaining`，不自行伪造精确值。
- Key 不匹配、IP 白名单不符、限流或网络错误时显示明确错误，不用旧数据冒充新结果。
- 运行过程中显示的递减值可标注为“预计剩余”；批次结束后重新查询实际值。
- 批次结束复查失败时保留已完成结果，并在日志中明确提示复查失败，不用旧值冒充新结果。

### 5.3 输入校验

**FR-VAL-001：启动前校验**

- Key 去除首尾空白后不能为空。
- 类别和地区必须来自有效选项。
- 源目录必须已存在、是目录且可读；启动前使用实际可读/可进入探测。
- 目标目录不存在时自动递归创建；存在时必须是目录且可写，创建后使用实际可写/可进入探测。
- 源目录与目标目录不得相同。
- 目标目录可位于源目录内部，但扫描必须排除目标目录树。
- 源目录位于目标目录内部时应拒绝，避免目录关系不清及重复归档。
- 路径校验使用规范化后的绝对路径，不仅比较字符串。

**FR-VAL-002：单图校验与上传准备**

仅处理扩展名为 `.jpg`、`.jpeg`、`.png` 的普通文件，扩展名不区分大小写。上传前验证：

- 原文件必须可读、可解析，宽和高均不得低于 11 像素。
- 原图不超过 2,000,000 字节且宽高均不超过 8192 像素时直接上传原图，不创建压缩副本。
- 原图超过 2,000,000 字节或任一边超过 8192 像素时，必须先生成临时 JPEG；临时图不得超过 2,000,000 字节，且宽高均在 11～8192 像素之间。
- 临时文件写入软件专用的系统临时目录，不得放在源目录或目标目录，不参与扫描和归档。

格式、尺寸或压缩结果校验失败时不调用 API、不复制图片，写入失败记录并继续下一张。

**FR-IMG-001：超限图片临时压缩**

- 压缩过程不得修改源文件内容、尺寸、格式、时间戳或元数据。
- 可调整临时图 JPEG 质量；仅靠质量调整仍超限时，可等比例缩小临时图，但不得裁剪主体。
- PNG 含透明度时使用白色背景合成后转为 RGB JPEG，避免透明区域变黑。
- 临时图仅用于本次 API 上传，每张原图仍只提交一次识别，不增加额外识别次数。
- 获得识别终态后立即删除临时图，再进入人工复核或复制；上传失败、轮询失败、识别超时、用户停止及其他异常路径也必须通过 `finally` 等等价机制清理。
- 清理失败时不得把临时文件复制到物种目录，也不得影响原图；当前实现未单独立清理警告，异常会终止批次。程序启动时清理过期临时文件仍为后续目标。
- 最终归档始终复制原始文件，而不是临时压缩图；人工复核弹窗也始终预览原图。
- CSV 记录本次是否使用压缩副本及原图/上传图字节数，不依赖临时文件路径进行断点恢复。

### 5.4 扫描与断点续跑

**FR-SCAN-001**

开始分类时递归遍历源目录中的支持图片，按规范化相对路径排序，保证处理顺序稳定。排除：

- 目标目录及其所有子目录（当目标位于源目录内时）。
- 历史 CSV、临时文件及软件日志。
- 符号链接造成的目录循环；v1 默认不跟随目录符号链接。

**FR-CSV-001：记录位置**

在源目录根目录维护 `birdclass_records.csv`，采用 UTF-8 with BOM，便于 Excel 正确显示中文。CSV 至少记录：源相对路径、文件身份、状态、分类时间、识别类别、地区、观测地点、观测时间、resultid、物种 ID、中文名、置信度、目标路径、错误信息与更新时间。人工复核还须记录 `selection_mode`（auto/manual）、`review_reason`、`candidate_payload`（去重候选及置信度快照）、阈值和人工复核时间，确保可追溯、可恢复。

**FR-CSV-002：启动读取**

每次开始分类前必须读取 CSV：

- 最新状态为 `completed` 且文件身份一致：跳过，不调用 API、不重复复制。
- 最新状态为 `recognized` 且文件身份一致：使用已保存的物种和目标路径续拷，不重新识别。
- 最新状态为 `review_pending` 且文件身份一致：从候选快照恢复人工复核弹窗，不重新识别。
- 文件身份变化：视为新的待处理图片，旧复核或识别结果不得复用。
- 最新状态为 `failed`：满足本轮条件时重试。
- 没有记录：正常待处理。

**FR-CSV-003：写入可靠性**

- 状态变化后及时写入并 flush，避免整批结束才记录。
- 写入失败时停止处理新图片并显示错误；不能在记录不可用时继续消耗额度。
- CSV 缺表头、编码损坏或关键字段非法时停止并提示用户备份/修复；不得静默覆盖。
- 同一图片允许多条事件记录，以同文件身份的最后一条有效状态为准。

### 5.5 懂鸟识别

**FR-API-001：上传**

对通过校验的图片发送 `multipart/form-data`：

- Header：`api_key: 用户输入`。
- `image`：未超限时为原图二进制；超限时为符合大小和尺寸限制的临时压缩 JPEG 二进制。
- `upload=1`。
- `class`：UI 类别代码。
- `area`：UI 选择具体地区时传地区代码；选择全球时省略该参数（真实服务端不接受 `WORLD`）。
- `did`：v1 不传。

只有返回业务码 `1000` 并取得 `resultid` 才表示受理成功。

**FR-API-002：轮询**

使用同一接口提交 `resultid`。以单调时钟计算总等待截止时间，处理中返回 `1001` 时按“剩余时长与 1 秒中的较小值”等待再查；默认总等待 60 秒，可由 UI 调整为 1～600 秒。截止时间包含网络请求耗时，到期记为“识别超时”，当前图片不复制并继续下一张，不新增待续查状态。HTTP 与业务状态必须分别校验，不能把 HTTP 200 等同于识别成功。

**FR-API-003：候选整理与自动选择**

成功结果可包含多个目标框，每个目标框可包含多个候选。软件保留每个目标框，先在框内按“物种 ID + 动物类别”去重并排序，再独立应用两个阈值。不同检测框的候选不得合并后比较前两名。每轮复核后，对已自动通过或人工确认的目标跨框按物种去重并归档；同一张图片的每个不同鸟种复制一次，同种鸟出现在多个框中仍只复制一次。

物种中文名、英文名、拉丁名从 `中文名|英文名|拉丁名` 字段拆分；缺失部分留空，但不能因英文名或拉丁名缺失而丢弃有效中文名。

真实 API 联调已确认候选置信度直接为 0～100 的百分数。API 适配层校验该范围，UI 和阈值比较统一使用这一标准值。满足以下全部条件时才自动选择第一名：

- 最高置信度大于或等于“低置信度复核阈值”，默认 80%。
- 只有一个不同物种候选，或第一名与第二名的置信度差大于“近似并列复核阈值”，默认 10 个百分点。

**FR-API-005：人工复核触发**

出现以下任一情况时必须弹出人工复核窗口，不得直接自动归档：

- `最高置信度 < 低置信度复核阈值`。
- 至少两个不同物种候选，且 `第一名置信度 - 第二名置信度 <= 近似并列复核阈值`。
- 两种条件同时满足时，弹窗同时展示两个原因。

阈值使用包含边界的上述比较规则。人工复核直接使用本次 API 已返回的候选，不再次上传、不额外消耗图像识别次数。

**FR-API-006：人工复核弹窗**

弹窗必须包含：

- 当前源图片的清晰预览，保持宽高比，可缩放窗口；高亮当前检测框，同时显示“目标 N/M”和源相对路径。
- 当前检测框的触发原因，以及该框实际最高置信度和前两名差值（若适用）。
- 仅当前检测框去重后的候选，按置信度降序排列；每项显示物种中文名、英文名、拉丁名（若有）和百分比置信度，候选行高必须容纳这些信息，不得用省略号截断。
- 单选控件，默认选中第一候选；候选过多时使用滚动区域，不得截断选项。
- 候选均不正确时使用的“人工确认鸟名”文本框与“按人工鸟名归档”按钮；文本框为空或仅含空白字符时按钮禁用。
- 可选复选框“后面同样（应用到本图剩余目标）”：默认不勾选；勾选后，确认候选或按人工鸟名归档时，当前选择应用到本图后续所有尚未确认的检测目标；每个目标仍单独生成选择并写入检测快照。
- “确认所选鸟种”“稍后处理（仅当前目标）”“停止本批次”按钮。

确认后保存当前框选择，即使其置信度较低也允许，并继续下一个未确认目标。选择“稍后处理（仅当前目标）”时，只为当前框保留未选择状态，随后继续其他目标，不再跳过整张图片。本轮结束后，自动通过和已确认的物种立即按物种去重并复制；仍有推迟目标时整图保持 `review_pending`，同时保存完整检测快照及已归档物种的目标路径，并将原图复制到 `目标目录/待复核/`。同一图片有多个推迟目标时只生成一个待复核副本，已确认物种不受影响。下次运行只询问未确认目标，不重新调用识别 API，也不重复复制已归档物种或待复核副本。全部目标确认后才写入 `recognized/completed`，已有待复核副本保留，不自动删除。选择“停止本批次”时保留记录，但不再处理后续图片，也不生成待复核副本。

候选均不正确时，用户可以输入鸟种中文名并按人工鸟名归档当前目标。提交时去除名称首尾空白；名称为空或仅含空白字符时不得提交。人工名称作为人工候选参与后续流程：物种 ID 为 `manual:<中文名>`，动物类别继承当前检测目标，英文名与拉丁名为空，`confidence_raw` 记为 `manual`。内部数值置信度使用 0 以满足现有数据结构，但不表示 API 返回了 0%，界面与文档不得如此宣称。

同图多个目标输入相同人工鸟名时按人工物种 ID 去重，只复制一次；不同人工鸟名分别归档。人工鸟名可与自动选择、API 候选确认和“稍后处理”在同一张图片中混用。人工鸟名归档沿用既有目录清洗、`观测地点_观测时间_鸟种中文名_编号.扩展名` 命名、原图与复制件元数据、CSV 写入和断点续跑规则；`selection_mode` 记为 `manual`，CSV 中可通过 `manual:` 前缀追溯来源。恢复 `review_pending` 时保留已提交的人工选择，不要求重新输入或重新上传。

勾选“后面同样”只影响当前目标之后、尚未确认的目标，不回溯已确认、已推迟或已自动选择的目标；稍后处理和停止本批次不使用该选项。套用时优先使用后续目标候选列表中的同物种候选（若存在），否则复用当前选择；日志记录套用目标数量。所有被套用目标仍逐个写入 `detection_payload`，归档阶段继续按物种去重。

如果预览图片无法加载，不得静默改为自动分类；显示错误并允许用户选择候选、暂不分类或停止本批。

**FR-API-004：无有效结果**

返回空候选、未检测到目标框（1008）、未识别到动物（1010）或其他单图终态失败时，不创建物种目录、不复制，记录失败并继续下一张。地区内无匹配物种（1011）属于单图失败：记录失败原因，将原图复制到 `目标目录/待复核/`，计入待复核数量，然后继续下一张，不创建物种目录。地区代码错误（1005/1009）仍按地区配置问题处理：当前图片记录失败，并停止整批、提示检查地区，避免后续图片重复失败。

### 5.6 复制与命名

**FR-COPY-001：目录**

识别成功后，在目标根目录下创建清洗后的物种中文名目录。目录已存在则直接复用。中文名为空时视为结果解析失败，不复制到无意义目录。

**FR-COPY-002：目录名清洗**

保证 Windows 可用：移除或替换 `<>:"/\|?*`、控制字符、末尾空格和点，处理 `CON`、`PRN`、`AUX`、`NUL`、`COM1` 等保留名，并限制过长名称。清洗结果为空时使用 `未命名物种_<物种ID>`。CSV 保存原始名称和实际目标路径。

**FR-COPY-003：元数据与文件名**

- 原图和归档复制件均写入最终确认的鸟种中文名；JPEG 使用 EXIF `ImageDescription` 和 `XPKeywords`，PNG 使用 `Description` 和 `Keywords`。
- 元数据写入不得重编码 JPEG 或改变图片像素，应采用临时文件原子替换；写失败则不复制并报告错误。
- 用户已明确接受原图从只读改为可写：分类会改变原图的元数据、文件大小和修改时间，但不移动或删除原图。界面与文档应提示先备份重要图库。
- 新任务复制件命名为 `观测地点_观测时间_物种中文名_编号.扩展名`，例如 `云南大理_2026-10-24 1430_短趾雕_001.jpg`；各组件分别清理文件名非法字符，源图片不改名。
- 编号在相同“观测地点 + 观测时间 + 物种”目录内从 001 递增，跨 JPG/JPEG/PNG 统计，保留源扩展名。
- recognized/review_pending 恢复沿用 CSV 保存的观测信息，不受当前 UI 修改影响；v1/v2 旧记录没有观测信息，继续按原“地区_物种中文名_编号”规则恢复。
- recognized 恢复优先使用 CSV 已保存目标路径；同内容直接复用，不同内容不得覆盖。
- 复制完成前使用临时文件，避免中断留下看似完整的半成品。

**FR-COPY-004：状态顺序**

1. API 返回候选后，先判断是否需要人工复核；需要时写入含候选快照的 `review_pending`，用户确认后再继续。
2. 自动选择或人工确认有效物种后，计算安全目标路径。
3. 写入 `recognized` 及 resultid、物种、候选信息、选择方式、复核原因和目标路径。
4. 向原图写入鸟种元数据，再安全复制到规范命名的目标路径。
5. 重新读取原图大小和修改时间，追加更新身份的 recognized，再写入 `completed` 和分类时间，确保下次跳过。
6. 复制失败写入 `failed`，保留识别、检测和归档快照；下次应优先续拷而不是重新识别。配置错误和网络错误同样写入 `failed`（轮询网络错误保留 resultid；上传响应丢失标注“结果未知”）后停止批次。

**FR-COPY-005：待复核副本**

- 任一目标选择“稍后处理”后，在本轮复核收尾时复制原图到 `目标目录/待复核/原文件名.扩展名`，同图多个推迟目标只调用一次复制。
- 推迟目标有 API 检测框时，额外生成 `原文件名_待确认框.扩展名` 标注副本：在副本上以橙色框和目标编号标出这些检测框；同图多个推迟目标画在同一标注副本。
- API 未返回检测框、v1 旧记录或 1011 无分类结果时只复制原图，不生成标注副本。
- 标注副本仅用于直观查看，不写入未确认物种元数据；原图副本保留原文件名和已有元数据。标注生成失败时保留原图副本并继续复核流程。
- 待复核副本不套用鸟种目录和观测信息命名，不写入未确认鸟种元数据；原图已有的已确认鸟种元数据随复制保留。
- 同名同像素文件直接复用；同名不同内容从 `_002` 递增，禁止覆盖；标注副本另行按 `_待确认框`、`_待确认框_002` 递增。重复推迟和恢复运行保持幂等。
- 已确认目标仍按 FR-COPY-001～004 归档；`STOP` 不生成待复核副本；后续全部确认后保留已有待复核副本。

### 5.7 额度控制与停止

**FR-STOP-001：额度不足**

开始新识别前查询实际图像额度。设本轮新识别待处理数为 N、剩余额度为 R：

- 普通额度且 R=0：不上传任何新图片，提示额度不足并停止。
- N>R：仅允许最多 R 张新图片被受理，其余保持未处理，达到批次上限后停止并提示。
- N≤R：可处理全部 N 张。
- 无限额度：不因本地数量设上限。
- 已识别待续拷任务不占用新识别名额，可优先完成复制。
- `review_pending` 的恢复复核也不占用新识别名额；即使剩余为 0，仍可打开弹窗、确认选择并完成复制。

软件按“每张成功受理的新图片消耗一个本地可用名额”保守控制，不依赖识别是否最终成功。由于其他客户端可能同时使用同一 Key，遇到服务端额度不足或限流信号时立即停止新上传。

**FR-STOP-002：用户停止与关闭**

- 用户点击停止后，不再上传新图片。
- 当前图片可完成轮询和复制，保证记录一致。
- 关闭正在运行的窗口时提示“停止并退出”或“取消关闭”；停止并退出会等待当前图片处理完成后关闭，不得直接杀死后台任务留下无记录状态。

### 5.8 日志与错误反馈

**FR-LOG-001**

UI 至少区分：输入错误、单图失败、额度停止、用户停止、全部完成。单图失败不导致整批崩溃；Key、地区、CSV 写入、目标目录不可写等全局错误应停止整批。

日志中 Key 仅可显示为脱敏形式，resultid 可保留用于排查。错误信息应包含源相对路径，但不能向用户只展示技术堆栈。

上传请求已发出但响应丢失时，错误信息必须标明“上传结果未知，重试可能再次消耗额度”；轮询网络错误保留 resultid。此类失败写入 `failed` 后停止批次。

## 6. 非功能需求

### 6.1 易用性

- 中文界面，字段名称清晰，常用默认项开箱可用。
- 路径既可选择也可粘贴；支持含空格和中文的路径。
- 长时间运行时持续显示当前文件和数量进度。
- 失败信息可帮助用户判断是图片、网络、Key、额度还是磁盘问题。

### 6.2 可靠性与数据安全

- 源文件仅允许写入既定的鸟种中文名元数据，不得重编码图像、移动或删除；UI 应明确提示这一写入行为。
- 不静默覆盖不同内容的目标文件。
- CSV 是断点续跑的事实来源，必须逐条持久化。
- 网络请求必须设置超时，不允许无限等待。
- 单个坏图片不得终止整批。

### 6.3 性能与规模

- v1 顺序上传，目标是在 10,000 张图片规模下仍可运行。
- 扫描和 CSV 读取不得阻塞 UI。
- 除当前图片、必要哈希和结果外，不把全部图片读入内存。
- 地区列表约 2,227 条，应提供搜索/过滤，不要求用户滚动查找。

### 6.4 安全与隐私

- 仅通过 HTTPS 访问官方 API。
- Key 不明文落盘、不进日志、不出现在错误截图所需的核心文本中。
- 图片会上传给懂鸟服务，UI 首次运行或关于页应提示此事实。
- 不将图片或 Key 发送到需求外的第三方服务。

### 6.5 可维护性与可测试性

- UI、API、扫描、CSV、复制和批处理逻辑分层，核心逻辑可无 UI 测试。
- API 使用可替换传输接口，自动化测试不消耗真实额度。
- 提供依赖锁定、测试命令、启动命令和版本信息。

### 6.6 解释器运行与兼容

- 当前使用 Python 3.11 和独立虚拟环境运行，不要求免 Python 环境。
- 安装项目及依赖后，在项目根目录通过 `python -m birdclass` 启动。
- 地区代码等资源通过包资源机制读取，不依赖开发机绝对路径。
- 保留控制台以便查看未捕获异常和诊断信息；正常运行日志仍不得包含 Key。
- 依赖清单、版本号和启动说明随源码提供。

## 7. 关键异常处理矩阵

| 情况 | 是否上传/继续上传 | 是否复制 | CSV | 整批行为 |
|---|---|---|---|---|
| 图片超过 2 MB 且可压缩到限制内 | 上传临时压缩图 | 复制原图 | 记录压缩信息 | 正常处理并清理临时图 |
| 原图/临时图尺寸非法，或无法压缩到 2 MB 内 | 否 | 否 | failed | 清理临时图，继续下一张 |
| 图片无法解析 / 压缩失败 | 否 | 否 | failed | 清理临时图，继续下一张 |
| 临时文件清理失败 | 当前请求不因此重发 | 仍复制原图 | 未单独记录警告；异常可能终止批次 | 启动清理尚未实现 |
| Key 不匹配 / IP 不允许 | 否，立即停止 | 否 | 可记全局日志 | 停止 |
| 地区代码错误（1009） | 否，立即停止 | 否 | failed + 日志 | 停止 |
| 类别或上传地区错误（1004 / 1005） | 否，立即停止 | 否 | failed + 日志 | 停止 |
| 上传 HTTP 网络错误 | 否，不自动重试 | 否 | failed，注明结果未知 | 停止；不重复消耗额度 |
| 轮询网络错误 | 否，不自动重试 | 否 | failed，保留 resultid | 停止 |
| 结果超时 | 当前批次不再查询该图 | 否 | failed，错误包含等待时长和 resultid | 继续下一张；下次按 failed 重试 |
| 1008 / 1010 | 否 | 否 | failed | 继续下一张 |
| 1011 | 否 | 原图复制到 `待复核` | failed，记录地区内无匹配物种 | 继续下一张 |
| 无候选或中文名缺失 | 否 | 否 | failed + 原始摘要 | 继续下一张 |
| 复制失败 | 否，停止新上传 | 失败 | failed，保留识别/归档快照 | 停止；下次优先续拷 |
| 目标磁盘满 / 无权限 | 否，停止新上传 | 尝试当前但失败 | failed | 停止 |
| CSV 无法写入 | 否，立即停止 | 不再开始新复制 | 无法写时记 UI 日志 | 停止 |
| 额度为 0 / 达批次上限 | 否 | 已识别续拷可完成 | 未处理项不写 failed | 明确停止 |
| 用户停止 | 不再上传新图 | 当前可完成 | 正常落盘 | 安全停止 |

> 对“请求已发出但响应丢失”的上传场景，任何客户端都无法完全排除服务端已受理的可能性。v1 不做自动重放，并在错误中标明“结果未知，重试可能再次消耗额度”。

## 8. 验收标准

### 8.1 配置与额度

1. 空 Key 点击查询或开始时，出现明确提示且不发送请求。
2. 有效普通额度响应能正确显示 used、total、remaining。
3. `total=-1` 显示无限额度，开始分类时不被数值 -1 误判为零。
4. Key 错误、IP 白名单错误和限流均有不同且可理解的提示。

### 8.2 扫描与续跑

5. 源目录含大小写混合的 JPG/JPEG/PNG 及子目录图片时均能发现；其他扩展名忽略。
6. 目标目录在源目录内部时，复制结果不会在后续扫描中成为新任务。
7. 预置 completed CSV 后，相同文件被跳过；改变文件内容或修改时间后重新进入待处理。
8. 预置 recognized CSV 后，软件不调用识别接口，直接完成复制并补写 completed。
9. failed 图片下次可重试；有完整快照的 failed 优先续拷或只恢复未确认目标，未处理图片不会因额度停止而被误标为完成。

### 8.3 识别与归档

10. 上传参数包含正确的 `upload=1`、class、area 和 Key，且不传 did。
11. 处理中响应会按 UI 配置的总等待时长轮询；默认 60 秒，到期仍未完成时记超时，不无限循环。
12. 多目标结果按每个检测框独立应用两个阈值；不同鸟种分别复制，同种鸟跨多个检测框只复制一次。
13. 识别成功后创建 `目标目录/中文名/观测地点_观测时间_中文名_编号.扩展名`；原图和复制件都能回读鸟种中文名元数据，像素与分类前一致。
14. 空候选、1008、1010 等失败结果不创建物种目录、不复制。
15. 含 Windows 非法字符的物种名可生成合法目录，CSV 能追溯实际路径。
16. JPG 后处理 PNG 等同前缀文件时编号继续递增，不覆盖已有不同内容。
17. recognized 恢复时目标已有同内容文件不产生无意义副本，并能记录完成；元数据写入后 CSV 身份更新，第二次运行跳过。

### 8.4 额度与中断

18. 10 张待处理、仅剩 3 次时，最多受理 3 张新图片，其余不处理，并显示额度停止原因。
19. 剩余 0 时不发起图片上传。
20. 已识别待续拷任务即使剩余 0 也能完成复制，因为它不需要新识别。
21. 处理中点击停止后不再受理新图片，当前记录保持一致。
22. 模拟复制后、CSV 写入前崩溃，下次不会覆盖不同文件；可能产生的重复 API 风险已在文档中说明。

### 8.5 人工复核

23. 默认阈值下，最高置信度为 79.99% 时弹窗；80% 且与第二名差值大于 10 个百分点时自动归档。
24. 前两名差值恰好为 10 个百分点时弹窗，大于 10 个百分点且第一名不低于 80% 时不弹窗。
25. 同一物种跨多个目标框重复出现时先去重，不得因同物种重复而误判为近似并列。
26. 弹窗能显示原图、全部去重候选的中文名、英文名、拉丁名及百分比置信度，名称不得被省略号截断；用户选择非第一名后，复制到所选物种目录，CSV 记录 manual 和复核原因。
27. 用户对一个目标选择“稍后处理”后仍继续后续目标，已确认物种先复制，原图在 `待复核/` 保留一份，有检测框时另生成带框标注副本；同图多个推迟目标不重复复制。重启后仅从 review_pending 恢复未确认目标，不再次调用识别 API，已完成物种和待复核副本均不重复复制。
28. 人工弹窗中选择“停止本批”后不再处理后续图片，当前候选快照仍保留。
29. 剩余额度为 0 时，已有 review_pending 仍能恢复复核并完成归档。
30. 图片预览加载失败时不自动归档、不崩溃，用户仍可查看候选并作出决定。

### 8.6 超限图片压缩

31. 大于 2,000,000 字节的 JPG/PNG 能生成合规临时 JPEG，API 实际上传内容不超过限制，归档文件与源图像素一致，鸟种元数据可回读。
32. 未超限图片直接上传，不创建临时压缩副本。
33. 仅调质量仍超限时，临时图可等比例缩小；任何边不得缩到 11 像素以下，无法合规则不上传、不复制。
34. 透明 PNG 使用白底合成上传，最终仍复制原始 PNG，临时 JPEG 不进入目标目录。
35. 成功、识别失败、轮询超时、网络异常、人工复核和停止路径均执行临时文件清理。
36. 临时文件位于软件专用临时目录，不被源目录扫描；CSV 有压缩标志和大小记录，断点恢复不依赖临时路径。
37. 超限图片触发人工复核时，弹窗显示原图且临时上传图已删除，确认后仍复制原图。

### 8.7 解释器启动

38. 在新的 Python 3.11 虚拟环境安装项目和锁定依赖后，`python -m birdclass` 能启动主界面，无 import 或资源路径错误。
39. 中文路径、空格路径、长路径常见场景可用；离线启动可展示界面，联网操作有明确错误。
40. 从项目根目录启动时地区下拉资源可用，日志和 CSV 写入预期的用户可写位置，控制台无正常运行的异常堆栈。

### 8.8 系统外观

41. 浅色与深色调色板下，主窗口、分组框、输入区、日志和复核候选区的文字与背景对比度均达到 4.5:1，且不存在固定白色主背景。
42. 模拟 `colorSchemeChanged` 后应用样式更新为新调色板颜色，无需重建主窗口或重启。
43. 浅色／深色主窗口及深色复核弹窗渲染检查后，输入提示、按钮、候选置信度和日志均可读，图片检测框位置不回归。

### 8.9 人工鸟名归档

44. 弹窗中鸟名输入框为空或仅含空白字符时“按人工鸟名归档”按钮禁用；输入有效名称后启用，提交后去除首尾空白。
45. 人工鸟名归档到 `目标目录/中文名/观测地点_观测时间_中文名_编号.扩展名`；原图与复制件均可回读该中文名元数据，像素不变。
46. CSV 完成记录包含 `species_id=manual:<中文名>`、`species_cn=<中文名>`、`selection_mode=manual` 和复核原因，可追溯为人工输入。
47. 同图两个目标输入相同人工鸟名时只产生一个复制件；输入不同名称时分别归档；其他目标仍可自动通过、稍后处理或按 API 候选确认。
48. 人工鸟名与“稍后处理”混用后重启，只恢复未确认目标，不重新上传，已人工归档物种与待复核副本均不重复复制。

### 8.10 额度复查与失败落盘

49. 批次结束时重新查询额度并更新界面显示；只有续拷或复核、无新上传的批次同样复查。
50. 批次结束复查失败时，已完成结果与批次摘要仍保留，日志明确提示复查失败，不用旧额度冒充新值。
51. 源目录不可读或不可进入、目标目录不可创建或不可写时，启动前给出明确错误，不开始扫描。
52. 运行中关闭窗口弹出“停止并退出/取消关闭”；取消后继续运行；确认后等待当前图片处理完成再关闭，不强制终止线程。
53. 1004/1005/1009 配置错误、上传/轮询网络错误和复制失败均写入 `failed`，包含 error_code 和 error_message；轮询网络错误保留 resultid，上传响应丢失标注“结果未知”。
54. 复制失败或部分复核复制失败后重启，有完整快照的 `failed` 优先续拷或只恢复未确认目标，不重新上传；无快照的失败按待处理重试。

### 8.11 后续目标同样处理

55. 复核弹窗默认不勾选“后面同样”；勾选并确认候选或人工鸟名后，本图后续未确认目标不再弹窗，且每个目标都写入独立的 `TargetSelection` 和 `detection_payload`。
56. 同群多个目标被套用同一物种时只产生一个鸟种复制件，`summary.reviewed` 计入全部套用目标，日志显示套用目标数量。
57. 未勾选时仍逐个目标复核；已自动选择、已推迟和已确认的目标不会被回溯覆盖，稍后处理和停止本批次不受该选项影响。

### 8.12 待复核标注副本

58. 推迟目标有检测框时，待复核目录同时存在原图副本和 `原文件名_待确认框.扩展名` 标注副本；标注副本用橙色框和目标编号标出待确认检测框。
59. 同一图片多个推迟目标只生成一个标注副本，所有对应框画在同一副本；标注内容变化时按 `_待确认框_002` 递增，不覆盖不同内容。
60. API 未返回检测框、v1 旧记录或 1011 无匹配物种时，只复制原图，不生成标注副本。
61. 标注生成失败时原图副本仍存在，复核与断点续跑状态不受影响；完成复核后待复核副本不自动删除。

## 10. 待评审但已采用的默认项

本轮为避免阻塞开发，以下按推荐方案直接写入需求；如需调整，应在实现前修改文档：

- 扫描包含子目录，而非仅源目录第一层。
- 支持 B/M/A/R 单类别，默认 B；不支持组合类别。
- UI 以 `WORLD` 表示全球，上传时省略 `area` 参数。
- 默认低置信度复核阈值为 80%，近似并列阈值为前两名差距不超过 10 个百分点；两者均可在 UI 调整。
- 触发复核时先保存候选快照，跳过或停止均可在下次恢复，不为重复弹窗重新消耗识别额度。
- 失败图片保留在源目录，下次重试；不归入“未识别”目录。
- 记录文件固定为源目录下 `birdclass_records.csv`。
- 默认不持久化 Key。
- 每轮按开始时的剩余额度限制新上传数量，而不是一张图查询一次额度。
- 候选都不正确时允许人工输入鸟种中文名，物种 ID 使用 `manual:<中文名>`，英文名与拉丁名留空，内部置信度为 0 但保留 `confidence_raw=manual` 区分来源。

## 11. 归档浏览与纠错（2026-10-26 追加）

分类完成后用户会删除源目录，只保留分类后目录。因此新增查看/纠错能力，且不依赖 CSV 或源图：

- 查看页按界、门、纲、目、科、属、种虚拟分类树浏览分类后目录；树只显示实际存在的物种，并随归档/纠错/外部变化增量更新，不要求重启。
- 分类树支持中文/中英/拉丁切换，默认中文；左中右三栏宽度可拖动。
- 搜索支持中文、英文、拉丁名、路径、拼音全拼和拼音首字母，并提供输入联想与回车确认。
- 查看页使用 SQLite 缓存 entries/groups/batches，分类树增量更新；支持观测地筛选和多种排序。
- 批次页提供失败/待复核 group 清单；查看页支持全屏 Lightbox。
- 批次结果页提供“确认结果并关闭”按钮。
- 待复核/失败图片支持人工填写（带中文/拼音联想）、无鸟、非鸟动物（可备注）、风景、已分类、稍后处理；人工归档复用已有物种副本、只处理未确认目标，完成后停留在待复核页面。
- 待复核副本文件名包含观测地点和观测时间；没有 group 的旧待复核文件也可补建 group 后人工复核。
- 图片详情显示目、科、属、种的中文名、拉丁名和英文名。
- 右侧图片区和详情区之间支持拖动调整高度。
- 归档时自动在分类后目录的 `.birdroost/` 保存 group（检测框、目标选择、副本映射）、batch（批次汇总）和 corrections（纠错记录）。
- 查看页“显示检测框”默认关闭；批次结果页默认开启。没有检测框数据的旧图片仍可浏览。
- 检测框必须从上传图坐标正确换算到原图显示坐标，覆盖压缩缩放、EXIF 旋转和 PNG/JPEG。
- 批次结束默认自动打开本次批次结果页，可在设置中关闭；批次页按 batch_id 过滤。
- 查看页和人工复核弹窗支持缩放、拖动、适应窗口、1:1；查看页支持复制干净图/带框图到剪贴板。
- 纠错只修改归档副本：查看页为副本级，批次页为目标级；整份副本直接移动，不额外复制到 `已纠正/`，共享副本拆分时保留旧副本。
- 物种选择支持 taxonomy 别名和自定义人工鸟名；用户可为 IOC 物种保存检索别名。
- 纠错不修改源图、不修改 `birdclass_records.csv`；CSV 继续只服务分类断点续跑。
- 分类学数据使用 IOC 15.2 精简快照，覆盖鸟纲中国与西古北界物种；目/科中文名缺失时回退拉丁名，并保留第三方署名。

验收：现有 130 项回归测试保持通过；新增归档库、坐标、查看页、批次页、缩放/剪贴板、动态树和纠错测试；在源目录删除后仍能浏览和纠错。
