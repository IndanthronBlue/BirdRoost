# 人工填写鸟名归档设计

日期：2026-10-25
状态：已获用户确认

## 目标

在人工复核弹窗中允许用户绕过 API 候选，直接输入确认后的鸟种中文名。当前检测目标按该名称归档，同时复用现有命名、元数据、CSV 和断点续跑机制。

## 交互

- 在候选列表下方增加“人工确认鸟名”文本框和“按人工鸟名归档”按钮。
- 文本框为空或只有空白字符时按钮禁用；输入有效内容后启用。
- 提交时去除首尾空白，弹窗关闭并返回新的人工输入结果类型。
- 原“确认所选鸟种”“稍后处理（仅当前目标）”“停止本批次”行为不变。

## 数据与处理流程

- `ReviewAction` 新增 `CUSTOM`，`ReviewResult` 增加可选 `custom_name_cn`。
- Service 收到 `CUSTOM` 后为当前检测目标构造人工候选：中文名取用户输入，动物类别继承当前目标，物种 ID 使用带 `manual:` 前缀的稳定值，英文名和拉丁名为空。
- 人工输入不代表 API 给出了 0% 置信度；内部仅用数值 0 满足现有候选数据结构，并以 `confidence_raw="manual"` 和人工物种 ID 明确区分来源。
- 选择方式沿用 `manual`，由人工物种 ID 和 `confidence_raw` 保留可追溯性。
- 后续继续走现有部分归档、全部完成、CSV 事件和恢复流程，不在弹窗中直接复制文件。

## 归档规则

- 目录使用现有安全清洗后的鸟种中文名。
- 文件名继续使用 `观测地点_观测时间_鸟种中文名_编号.扩展名`。
- 原图和复制件继续写入最终确认的鸟种中文名元数据。
- 同图多个目标输入相同鸟名时，依靠稳定的人工物种 ID 在现有跨框聚合阶段去重，只复制一次。
- 不同鸟名分别复制到对应目录；已自动通过、API 候选确认、人工输入和稍后处理可在同一张图片中组合。

## 异常与边界

- 空白名称不允许提交；非 UI 调用缺少有效人工名称时抛出受控识别错误。
- 非法路径字符、Windows 保留名、同名冲突和编号由现有归档层处理，不新增另一套规则。
- 复制、元数据或 CSV 失败仍按现有全局或单图错误策略处理。
- 恢复 `review_pending` 时保留已经人工输入的选择，不要求重新上传或重新输入。

## 测试

- 弹窗：空白禁用、有效输入启用、提交动作和去除首尾空白。
- Service：人工鸟名归档到预期目录，CSV、命名和元数据正确。
- 多目标：相同人工鸟名去重，不同人工鸟名分别归档，其他目标仍可自动通过或稍后处理。
- 恢复：部分人工输入后的 `review_pending` 可续跑且不重复上传、不重复复制。
- 运行完整自动化测试，确认原候选确认、推迟、停止和系统外观行为不回归。
