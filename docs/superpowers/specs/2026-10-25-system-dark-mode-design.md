# 羽栖 BirdRoost 系统深色模式适配设计

- 日期：2026-10-25
- 范围：macOS 当前验证环境；不改变识别、复核、归档和 CSV 行为

## 问题

主窗口将背景写死为浅灰、分组框写死为白色。系统进入深色外观后，Qt 原生文字和控件可能切换为深色配色，而这些固定背景仍保持浅色，导致视觉风格割裂及对比度不稳定。应用也没有在系统外观变化后主动重建自定义样式。

## 方案比较

1. **完全删除自定义样式**：最依赖原生行为，但会失去现有分组框间距、圆角和控件尺寸，且不同 Qt 版本下样式表现不易测试。
2. **按系统 QPalette 生成集中样式**：保留布局风格，颜色全部来自当前系统调色板，可用浅色和深色调色板自动测试；采用此方案。
3. **手写固定深色 QPalette**：容易覆盖用户系统 accent color，且需要自行维护所有控件状态，不采用。

## 设计

新增 `birdclass.ui.theme`：

- `application_stylesheet(palette: QPalette) -> str` 从 `Window`、`Text`、`Base`、`AlternateBase`、`ButtonText`、`Highlight`、`HighlightedText`、`Mid` 等角色生成应用样式。
- `SystemThemeController` 在初始化时应用样式，并连接 `QApplication.styleHints().colorSchemeChanged`。信号触发时重新读取当前应用调色板并生成样式。
- `install_system_theme(app)` 创建以 `QApplication` 为父对象的控制器，保证生命周期覆盖整个应用。

主窗口仅保留界面结构和业务行为，不再设置局部浅色样式。输入框、下拉框及其弹出列表、候选列表和日志均使用调色板颜色。复核图片预览继续使用固定深色底板和白色占位文字，橙色检测框不变；它们承载的是图片查看功能，不是窗口背景。

## 验收标准

1. 浅色外观保持可读，深色外观不再出现写死的白色主窗口或分组框。
2. macOS 外观在应用运行中变化时，自定义样式随当前调色板刷新，无需重启。
3. 主窗口、设置输入区、日志、复核候选列表及下拉弹出列表的前景色和背景色来自同一调色板。
4. 复核图片缩放、检测框位置、逐目标操作及全部分类测试不回归。
5. 自动化测试覆盖浅色／深色对比度、移除固定浅色规则以及主题变化信号触发刷新；补充离屏截图进行视觉检查。
