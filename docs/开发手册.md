# 羽栖 BirdRoost 开发手册

- 文档版本：v1.11（人工鸟名归档与候选显示版）
- 编写日期：2026-10-25
- 对应需求：`docs/需求文档.md`
- 技术路线：Python 3.11 / 3.12 + PySide6 + Requests + Pillow + piexif，解释器直接启动
- 当前状态：96 项自动化测试通过；已检查浅色／深色主窗口、深色复核弹窗及候选两行名称的离屏渲染，本轮验证不消耗 API 额度

## 1. 开发目标与原则

实现一个通过 Python 解释器启动的桌面工具，将本地图片交给懂鸟 API 识别，复制到物种中文名目录，并用源目录中的 CSV 保证可续跑。

开发优先级依次为：

1. 尽量避免重复消耗额度，不损坏或覆盖用户图片；对无法消除的外部 API 中断窗口如实提示。
2. UI 不冻结，中断后状态一致。
3. 核心逻辑可自动化测试。
4. 在独立 Python 3.11 虚拟环境中可重复安装、测试和启动。
5. 界面美观和附加体验。

不得为了简化实现而省略 resultid 轮询、CSV 落盘、额度控制、输出目录排除或同名文件保护。当前阶段不引入打包工具或 EXE 构建工作。

## 2. 技术方案比较与选择

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| PySide6 | 成熟桌面能力；后台线程与信号完善；可搜索下拉框；适合复杂复核弹窗 | 第三方依赖较大 | 推荐，适合本项目的可靠桌面应用 |
| Tkinter | 标准库 UI、依赖少 | 复杂下拉、线程 UI 和现代交互成本较高 | 可做精简版，但不作为首选 |
| CustomTkinter | 外观较现代、上手快 | 复杂组件与长期兼容性仍依赖 Tk | 不作为核心可靠性项目的首选 |
| 本地 Web UI + 浏览器 | UI 开发灵活 | 还需管理本地服务、端口与生命周期 | 超出当前需要 |

当前通过 Python 3.11 解释器运行，不使用 PyInstaller，不考虑 EXE、安装包或代码签名。

## 3. 总体架构

采用单向调用的分层结构：

```text
MainWindow（UI）
   │ 用户配置 / 按钮事件
   ▼
Worker / QThread（后台任务）
   │ 构造并启动
   ▼
ClassificationService（批次编排、额度、停止）
   ├── SourceScanner（扫描与排除）
   ├── CsvHistory（读取、状态恢复、追加）
   ├── ImageValidator（原图格式与尺寸）
   ├── UploadPreparer（超限临时压缩与清理）
   ├── DongNiaoClient（上传、轮询、额度）
   ├── SpeciesSelector（候选解析与选择）
   └── FileArchiver（目录清洗、冲突、复制）
```

依赖规则：

- UI 不直接发 HTTP、复制文件或写 CSV。
- Service 不 import PySide6，保证可用普通 pytest 测试。
- API Client 不决定文件是否完成，只返回结构化结果或受控异常。
- CSV 状态由 Service 按固定顺序推进。
- 后台线程通过信号向 UI 发送进度，禁止从子线程直接操作 QWidget。

## 6. 数据模型

建议使用 `dataclass(frozen=True)` 和 `Enum`，避免在层与层之间传递无约束字典。

### 6.1 AppConfig

字段：

- `api_key: str`：仅内存，脱敏 repr，禁止日志输出。
- `animal_class: str`：B/M/A/R。
- `area_code: str`：默认 WORLD。
- `observation_location: str`：观测地点，新任务 UI 必填，用于复制件命名。
- `observation_time: str`：观测时间，新任务 UI 必填，保留自由文本格式。
- `low_confidence_threshold: Decimal`：默认 80，单位 %，范围 0～100。
- `ambiguity_delta_threshold: Decimal`：默认 10，单位百分点，范围 0～100。
- `source_dir: Path`。
- `output_dir: Path`。

### 6.2 ImageItem

- `absolute_path: Path`。
- `relative_path: str`：统一使用 `/`，便于跨平台 CSV。
- `size: int`。
- `mtime_ns: int`。
- `identity`：由相对路径、大小、mtime_ns 组成。

### 6.2.1 PreparedUpload

一次上传准备的上下文对象，字段包括：

- `original_path: Path`：不可替换，人工预览和最终归档只使用此路径。
- `upload_path: Path`：未超限时等于 original_path；超限时指向临时 JPEG。
- `original_bytes: int`、`upload_bytes: int`。
- `was_compressed: bool`。
- `temporary_path: Path | None`：仅软件创建的临时文件，cleanup 不得删除其他路径。
- `cleanup()`：幂等，只删除 temporary_path；所有退出路径均调用。

PreparedUpload 作为上下文管理器使用。API Client 只接收 upload_path，FileArchiver 只接收 original_path，从接口边界防止误把压缩图归档。

### 6.3 Quota

- `used: int`。
- `total: int`。
- `remaining: int`。
- `unlimited: bool`：由 `total == -1` 推导。

不要把无限额度存成剩余 `-1` 后直接参与普通减法。

### 6.4 RecognitionCandidate 与 Recognition

`RecognitionCandidate` 字段：

- `species_id: str`、`animal_class: str`。
- `name_cn/name_en/name_latin: str`。
- `confidence_raw: float | str`：保留 API 原值用于排查。
- `confidence_percent: Decimal`：统一为 0～100，用于显示、排序和阈值比较。
- `source_order: int`：稳定并列排序。

`Recognition` 表示最终选中的候选，另含：

- `result_id: str`。
- `selection_mode: auto | manual`。
- `review_reason: none | low_confidence | ambiguous | low_confidence+ambiguous`。
- `candidate_payload: str`：去重后的完整候选 JSON 快照。
- `reviewed_at: datetime | None`：人工确认时间。

手册未明确图片置信度的原始单位。API 适配层必须在真实联调确认响应后实现显式转换，核心层只接受 `confidence_percent`；禁止用“数值是否小于 1”猜测单位。阈值计算使用 Decimal，避免浮点边界误差。

### 6.4.1 ReviewResult 与人工鸟名

`ReviewResult` 表示一次复核答复：

- `action: ReviewAction`：`CONFIRM`、`CUSTOM`、`DEFER` 或 `STOP`。
- `candidate: RecognitionCandidate | None`：`CONFIRM` 时用户选中的候选。
- `custom_name_cn: str`：`CUSTOM` 时用户输入的鸟种中文名。

收到 `CUSTOM` 时，Service 先去除名称首尾空白，再构造候选：

- `species_id="manual:<中文名>"`，用于跨框去重和 CSV 追溯。
- `animal_class` 继承当前检测目标。
- `name_cn` 为用户输入，英文名与拉丁名为空。
- `confidence_raw="manual"`，`confidence_percent=Decimal("0")`，`source_order=-1`。

数值 0 只用于满足既有候选结构，不代表 API 给出 0% 置信度。人工名称为空或当前目标没有候选可继承动物类别时，抛出受控 `RecognitionFailedError`，不得静默回退为自动选择。

### 6.5 HistoryEvent

对应 CSV 一行事件。状态枚举：

- `review_pending`：已获得候选，等待人工选择；保存完整候选、触发原因和阈值。
- `recognized`：自动或人工选择完成，等待复制。
- `completed`：复制成功，完成。
- `failed`：校验、网络、识别、解析或复制失败。

未处理、额度停止不需要为每张图片伪造 failed 事件。人工“暂不分类”保留 review_pending，不改写为 failed 或 completed。

## 7. 懂鸟 API 接入规范

### 7.1 基本信息

- Base URL：`https://ai.open.hhodata.com`
- 接口：`POST /api/v2/dongniao`
- 鉴权：Header `api_key`
- 官方手册：https://ai.open.hhodata.com/doc/
- 地区附录：https://ai.open.hhodata.com/area-code

HTTP 200 只表示收到 HTTP 响应，业务结果还要检查 JSON 数组第一个元素的状态码。解析前检查 Content-Type、JSON 类型和数组长度，异常响应转为受控 `ApiProtocolError`。

### 7.2 额度查询

请求：

```http
POST /api/v2/dongniao
api_key: <用户Key>
Content-Type: application/x-www-form-urlencoded

quota=1
```

成功为 `[1000, payload]`。优先读取 `payload.image` 中的图像额度，同时兼容顶层 `used/total/remaining`。解析时验证三者关系，但遇到服务端新增字段不要失败。

业务码：

- 1000：成功。
- 1005：Key 不匹配、禁用或误用 web_token。
- 1006：IP 不在白名单。
- 1007：限流，HTTP 503；按Retry-After（若有）或退避，禁止紧密循环。

### 7.3 图片上传

请求字段：

```text
image = 二进制文件
upload = 1
class = B/M/A/R
area = 官方地区代码；UI 选择 WORLD 时省略此字段
```

真实服务端会拒绝 `area=WORLD`，因此全球不过滤必须省略 `area`。不发送 did。文件句柄用上下文管理器，确保异常时关闭。上传内容来自 `PreparedUpload.upload_path`，不得在此重新压缩或改动图片。临时文件至少保留到上传请求完成；识别终态后由 Service 立即 cleanup，再进入人工复核或归档，异常路径也在 finally 中 cleanup。

上传受理成功：`[1000, resultid]`。其他已知错误：

- 1001：图片大小错误。
- 1002：格式或尺寸错误。
- 1003：设备 ID 错误（本软件不传，若出现按协议异常）。
- 1004：动物类别错误，停止批次。
- 1005：地区错误，停止批次。

上传 POST 不做无条件自动重试。若请求已发出后连接超时，服务端可能已受理但客户端无 resultid，自动重试可能重复扣费。记录“上传结果未知”，交给用户下次有感知地重试。

### 7.4 结果轮询

请求 `resultid=<受理ID>`：

- 1001：结果未生成，在总等待截止前最多等待 1 秒再查。
- 1000：解析图像检测数组。
- 1008：未检测到目标框。
- 1009：地区错误，停止批次。
- 1010：未识别到动物。
- 1011：地区内无物种，抛出 `SpeciesNotFoundError`；Service 记录当前图片 `failed`，将原图复制到 `目标目录/待复核/`，计入失败与待复核数量，并继续下一张。

`poll_result(result_id, total_wait_seconds)` 使用单调时钟计算截止时间，总等待包含网络请求耗时；默认 60 秒，UI 可配置 1～600 秒。1001 时等待 `min(1, 剩余秒数)`，到期抛出 `RecognitionTimeoutError`，由现有单图失败流程记录并继续下一张，不新增待续查状态。连接超时 10 秒、读取超时 30 秒；连续网络错误达到 3 次则停止批次。

### 7.5 成功结果解析

官方描述的图像结果为检测数组，每个元素含：

- `box`：目标框坐标。
- `list`：最多 10 个候选，按置信度倒序。

候选项为 `[置信度, "中文名|英文名|拉丁名", ID, 动物类别]`。

实现步骤：

1. 验证 payload 是 list，以 `parse_detections(payload, prepared.upload_size)` 逐检测框解析，保留稳定 target_index。
2. box 按实际上传图宽高归一化，修复反序并截断越界；缺 box 时保留候选但不画高亮。
3. 在每个检测框内部将候选规范化为 RecognitionCandidate，用 `split("|", 2)` 解析名称；中文名为空的候选无效。
4. 仅先在当前框内按 `(species_id, animal_class)` 去重，再按置信度排序，禁止跨框合并候选后判断阈值。
5. 对每个非空框独立调用 `decide_candidate`：最高值低于阈值或前两名差值不超过阈值时复核，否则自动选择 top。
6. 空 list 框不产生归档任务；全部框为空才判整图识别失败。
7. 每轮复核后，对当前已确定的 TargetSelection 用 `aggregate_selections` 跨框按物种去重，每个物种生成一个 ArchiveSelection。
8. 需要复核时按 target_index 逐框弹窗，仅显示当前框候选；DEFER 只记录当前 target_index 为未选择并继续后续目标，不得中断整图复核。
9. 仍有未确认目标时保持 review_pending；已确定物种先归档，archive_payload 保存其目标路径。后续恢复只弹未选择目标，新选择合并进快照，已有物种复用原 destination_path，避免编号递增和重复复制。
10. 复核答复为 CUSTOM 时，以人工鸟名构造候选并作为当前目标的选择；它与其他选择一样参与跨框聚合、路径规划、元数据、CSV 和恢复，不触发额外上传。人工鸟名只替换候选，不改变检测框、阈值或复核原因。

不要写死 `payload[0]["list"][0]`。跨框同种只在最终归档阶段去重，不能因此触发近似并列；不同鸟种通过各自阈值后复制到多个目录。

### 7.6 错误分类

定义受控异常层级：

```text
BirdClassError
├── ConfigError              # 全局配置，停止
├── ApiAuthenticationError   # Key/IP，停止
├── ApiRateLimitError        # 限流，停止或退避
├── ApiQuotaError            # 额度，停止新上传
├── ApiTransportError        # 网络，有限处理
├── ApiProtocolError         # 非预期响应
├── ImageValidationError     # 原图校验失败，单图失败
├── ImagePreparationError    # 临时压缩失败，单图失败并清理
├── RecognitionFailedError   # 单图终态失败
├── HistoryError             # CSV，停止
└── ArchiveError             # 磁盘/权限，停止新任务
```

UI 将异常映射为中文，不直接暴露 Key 或完整请求头。

## 9. 扫描与路径安全

### 9.1 路径规范化

使用 `Path.expanduser().resolve()` 得到绝对路径。注意 Windows 大小写、UNC 路径、同一目录的不同表达。目录包含关系用 `Path.is_relative_to()` 或兼容实现，不用字符串 `startswith`。

启动规则：

- source 必须存在且可读。
- output 可创建，创建后做实际可写检查。
- source == output：拒绝。
- output 在 source 内：允许，但扫描时剪枝排除。
- source 在 output 内：拒绝。

### 9.2 扫描算法

使用可控的 `os.walk` 或等价递归：

1. 顶层向下遍历，不跟随目录符号链接。
2. 若当前目录是 output 或其父路径，修改 dirnames 剪枝。
3. 只收集普通文件和指定扩展名。
4. 排除历史 CSV 及临时文件。
5. 统一相对路径分隔符并排序。
6. 在收集每张时捕获权限错误，全局不可读则明确提示。

不要先用 `rglob("*")` 把输出目录全部枚举后再过滤，这会在大图库中浪费大量时间。

### 9.3 超限图片上传准备与临时压缩

常量 `MAX_UPLOAD_BYTES = 2_000_000`，保守按十进制 2 MB 限制实现，不使用更大的 2 MiB 替代。

`UploadPreparer.prepare(image_item) -> PreparedUpload`：

1. 用 Pillow 验证原图可解析且宽高不低于 11；`Image.verify()` 后重新打开图片再处理。
2. 原图字节数不超过上限且宽高均不超过 8192 时，直接返回 original_path == upload_path、was_compressed=False，不创建文件。
3. 字节数或边长超限时在系统临时根目录创建 `tempfile.TemporaryDirectory(prefix="birdclass-upload-")`，在其中生成随机、唯一的 `.jpg` 文件。源目录和目标目录均不作为临时位置。
4. 仅对临时副本应用 EXIF 方向校正；不裁剪。RGBA/LA/带 transparency 的 PNG 先合成到白色背景，再转换为 RGB，其他模式也规范化为 RGB。
5. 任一边超过 8192 时先按 `8192 / 最长边` 等比缩小；随后依次尝试 JPEG quality `85, 75, 65, 55, 45, 35, 25, 15`，使用 `optimize=True`，每次保存后检查实际字节数，首个合规结果即返回。
6. 若所有质量仍超限，将临时图宽高乘以 0.85 并向下取整，使用 LANCZOS 等比例缩小，再尝试质量 `75, 55, 35, 20`。重复缩放直到合规。
7. 任一目标边将小于 11、缩放不再产生更小尺寸或迭代超过 20 次时停止，抛出 ImagePreparationError；不上传、不复制。
8. 返回前重新打开临时 JPEG，验证格式、11～8192 尺寸和字节数。不得放大图片，也不把 EXIF、源路径或临时路径写入候选数据。

实现时把质量序列、缩放系数和上限定义成常量并测试，不在 UI 增加压缩参数。压缩只影响识别输入，可能降低识别准确率，因此不能将临时图用于人工预览或归档。

生命周期：

- 使用 `with UploadPreparer.prepare(...) as prepared:` 或等价 try/finally 包住上传和结果查询。
- 文件句柄和 Pillow Image 先关闭，再删除临时文件，兼容 Windows 文件锁。
- 得到识别终态后立即 cleanup，再进行人工复核或复制；上传、轮询、解析失败以及停止均执行同一 cleanup。
- cleanup 幂等，只允许删除本任务 TemporaryDirectory 内的文件。删除失败记录警告，不删除原图、不重发 API。
- 启动时可按严格目录名前缀和过期时间清理本软件崩溃遗留的临时目录，避免误删其他应用文件。

`FileArchiver.archive()` 的源参数只接受 `ImageItem.absolute_path` 或 `PreparedUpload.original_path`，禁止接受 upload_path。压缩图的 resultid 与原始文件身份绑定，后续 recognized/review_pending 恢复不需要临时图仍存在。

## 10. CSV 断点续跑设计

### 10.1 文件与编码

固定文件：`<source>/birdclass_records.csv`。

- 编码 `utf-8-sig`，新文件写 BOM，Excel 可直接显示中文。
- 使用 Python `csv` 模块和 `newline=""`，不要手写逗号拼接。
- 字段中含换行、逗号或 JSON 时由 csv 模块转义。
- 采用追加事件模式；启动时重放，每个文件身份取最后一条有效状态。

### 10.2 推荐表头

```text
schema_version,event_id,relative_path,file_size,file_mtime_ns,status,classified_at,class_code,area_code,result_id,species_id,species_cn,species_en,species_latin,confidence_percent,animal_class,destination_path,selection_mode,review_reason,low_confidence_threshold,ambiguity_delta_threshold,reviewed_at,candidate_payload,upload_was_compressed,upload_bytes,error_code,error_message,updated_at,detection_payload,archive_payload,observation_location,observation_time
```

说明：

- `schema_version` 新任务为 3；读取兼容 v1/v2，首次追加 v3 前原子迁移旧表头并分别保留 `birdclass_records.v1.bak` 或 `birdclass_records.v2.bak`。
- `observation_location`、`observation_time` 保存识别时的观测信息；后续 recognized/review_pending 恢复使用事件原值，不读取当前 UI 覆盖。v1/v2 旧记录这两列为空，继续使用旧地区命名。
- `event_id` 可用 UUID，便于排查。
- `classified_at` 仅 completed 必须有值，使用带时区 ISO 8601。
- `destination_path` 存代表性目标相对路径；多物种完整目标清单以 archive_payload 为准。
- `candidate_payload` 仅供 v1 单物种复核恢复；v2 使用 detection_payload。
- `detection_payload` 保存全部检测框、归一化 box、候选和逐框选择；每次人工确认后更新。
- `archive_payload` 保存跨框去重后的物种、来源目标和全部规划路径，recognized 恢复时据此续拷。
- `selection_mode` 为 automatic 或 manual；多目标事件只要包含人工选择即标记 manual。人工鸟名归档同样标记 manual，`species_id` 使用 `manual:<中文名>` 前缀，`confidence_percent` 为 0，用于区分来源。
- `review_reason` 记录 low_confidence、ambiguous 或组合原因，同时保存本次使用的两个阈值。
- `reviewed_at` 仅在人工确认后写入带时区 ISO 8601。
- `file_size` 是原图字节数；`upload_was_compressed` 表示是否使用临时压缩图，`upload_bytes` 是实际上传图字节数。无需保存临时路径，恢复时不得要求临时文件存在。
- `error_message` 不写入 Key、完整 HTTP Header。

### 10.3 读取与恢复

逐行验证字段类型；允许文件末尾最后一条不完整记录时，不擅自忽略：提示 CSV 可能因上次中断损坏，先备份再修复。对 schema_version 高于当前版本的文件拒绝写入，防止降级破坏数据。review_pending 还必须验证 candidate_payload 可解析且至少有一个有效候选，否则按损坏记录处理，不得自动重传掩盖问题。

建立索引：

```text
(relative_path, file_size, file_mtime_ns) -> 最新 HistoryEvent
```

恢复策略：

- completed：跳过。
- review_pending：重建候选列表和复核原因，加入 resume_review 队列；直接使用原快照，不重新上传。
- recognized：重建 Recognition 与目标路径，加入续拷队列。
- failed：加入新识别队列；若 error 阶段为 copy 且识别字段完整，可加入续拷队列。
- 文件身份不同：不沿用旧结果或候选快照。

### 10.4 写入与崩溃一致性

打开 CSV 追加写，每条事件后 `flush()`，必要时 `os.fsync()`。写 recognized 后才复制，写 completed 前确认临时文件已原子替换到最终位置。

CSV 无法写入时立即停止，不继续 API 调用。程序退出、用户停止或额度停止不删除 recognized 记录。

已知不可完全消除的窗口：上传已受理后、recognized 写入前进程被强杀，下一次可能重复识别。v1 明确接受并提示这一外部 API 限制；不得宣称“绝对不重复扣费”。

## 11. 分类批次状态机

### 11.1 批次流程

```text
校验 UI 输入（含 0～100 的两个复核阈值）
  → 创建/验证目标目录
  → 读取并验证 CSV（失败则停止）
  → 扫描源目录并排除输出树
  → 根据 CSV 分成 completed / resume_review / resume_copy / pending / retry
  → 优先执行 resume_review 和 resume_copy（均不占新识别额度）
  → 查询实际额度（失败则不上传）
  → 计算 new_upload_limit
  → 顺序处理 pending，直到完成、停止或达到上限
  → 重新查询额度
  → 输出批次摘要（含人工复核和暂不分类数量）
```

### 11.2 单张图片流程

```text
检查 stop_event 和本批上传名额
  → 校验原图格式、尺寸和文件身份
  → UploadPreparer：未超限用原图，超限时生成合规临时 JPEG
  → 上传 prepared.upload_path（受理成功才消耗本地名额）
  → 轮询 resultid
  → 解析、换算百分比、去重并排序候选
  → 识别终态或异常均 cleanup 临时图（在复核/复制前执行）
  → decide_candidate 判断自动选择或人工复核
  → 若需复核：先追加 review_pending（含完整候选、阈值和压缩信息）
  → 向主线程请求弹窗并等待决定，预览 original_path
  → 稍后处理：仅当前目标保持未选择，继续下一个目标
  → 停止本批：保留 review_pending，设置 stop_event
  → 人工鸟名：去除首尾空白后生成 manual:<中文名> 候选和 selection_mode=manual 的 TargetSelection
  → 确认选择：生成 selection_mode=manual 的 TargetSelection
  → 自动选择：生成 selection_mode=automatic 的 TargetSelection
  → 本轮复核结束：按事件中的观测信息和已确定物种规划安全目标路径
  → 向 original_path 写入已确定鸟种元数据并归档这些物种
  → 若仍有推迟目标：追加更新身份的 review_pending，保存全部选择和已归档路径，并复制一份原图到 待复核/
  → 若全部目标确定：依次追加 recognized、更新身份的 recognized、completed
  → 更新 UI
```

本地上传名额在收到 1000 受理后减一，而不是在识别成功后减一。达到 0 后不再上传，即使之前的图片识别失败，也保持保守策略。

### 11.3 取消

Worker 持有 `threading.Event`。每个图片开始前、网络请求之间、轮询等待期间检查。等待使用 `stop_event.wait(1)` 而不是不可中断的长 `sleep`。

QThread 生命周期由主窗口管理；退出时请求停止、等待线程完成，禁止 `terminate()` 强杀。

## 12. 文件归档算法

### 12.1 物种目录名

按 Windows 规则清洗：

1. 去除控制字符。
2. 将 `<>:"/\|?*` 替换为全角或安全字符，规则固定并可测试。
3. 去除末尾空格与点。
4. 检查 Windows 保留设备名（含带扩展名形式）。
5. 限制目录名长度，预留完整路径空间。
6. 空名称回退为 `未命名物种_<species_id>`。

不要对整段路径做同样的替换；只清洗单级目录名。

### 12.2 鸟种元数据

`metadata.write_species_metadata(path, species_cn)` 在复制前更新原图，复制件因此包含相同元数据：

- JPEG/JPG：使用 piexif 写入 EXIF `ImageDescription`（UTF-8）和 `XPKeywords`（UTF-16LE，以空字符结尾），不重新编码图像数据。
- PNG：使用 Pillow 写入文本块 `Description` 和 `Keywords`，保留已有文本、EXIF 和 ICC 配置，像素不变。
- 在源文件同目录创建临时文件，成功后 `os.replace` 原子替换；失败时清理临时文件并抛出 ArchiveError。
- 原图不再视为只读。鸟种写入会改变文件大小和修改时间，归档后必须重新 stat 原图。

### 12.3 文件名、编号与冲突

新任务目标路径固定为 `目标根目录/物种中文名/观测地点_观测时间_物种中文名_编号.扩展名`：

- 观测地点和观测时间取任务事件中的 `observation_location`、`observation_time`，各组件分别清理非法字符；恢复任务不受本轮 UI 改动影响。
- 编号从 001 开始，在相同“观测地点 + 观测时间 + 物种”完整前缀下取现有最大编号加一，跨 JPG/JPEG/PNG 统计，不能按扩展名分别编号。
- 保留源文件扩展名，例如 `云南大理_2026-10-24 1430_短趾雕_001.jpg`；源图片保持原名。
- v1/v2 旧记录没有观测信息，继续按 `地区_物种中文名_编号.扩展名` 恢复，不伪造观测数据。
- 新任务不覆盖已有不同内容；recognized 恢复使用 CSV 保存的 destination_path，同内容直接复用，不同内容另取新编号。
- 复制到目标目录的临时文件，成功后 `os.replace` 到目标；异常时清理临时文件。复制前后校验源文件身份。

归档完成后，按元数据写入后的原图大小和 mtime_ns 追加更新后的 recognized，再追加 completed。这样 completed 身份与磁盘原图一致，下次扫描能直接跳过，不会因元数据修改而重新上传。

### 12.4 待复核副本

`FileArchiver.archive_pending(item: ImageItem) -> Path` 专用于人工目标 `DEFER` 后的整图副本，目标根目录固定为 `输出目录/待复核/`：

- 文件名保留源 `stem + suffix`。原名已存在时用 `_same_pixels` 比较；一致则复用，不同则依次尝试 `_002`、`_003`，直到找到同内容文件或空路径，禁止覆盖不同内容。
- 复制复用 `_copy_atomic`，保持源文件变化检查、目标目录临时文件和 `os.replace` 语义。待复核方法不调用 `write_species_metadata`，因此不会写入未确认候选。
- `ClassificationService._finish_multi_review` 在 `deferred_targets` 非空时只调用一次。若已有选择，先执行 `_archive_partial_and_keep_pending` 保存鸟种副本和 CSV，再复制待复核文件；若没有选择，也直接生成待复核副本。
- schema 1 的单目标 `DEFER` 分支调用同一方法。`STOP` 分支不调用。后续全部确认不删除历史待复核副本。
- 待复核路径不进入 CSV，也不改变 schema；通过确定性文件名和像素比较保证恢复时幂等。服务发出 `deferred` 进度事件，主窗口记录目标路径。

## 13. UI 设计要点

### 13.1 布局

建议单窗口分组：

1. “API 设置”：Key、显示切换、查询按钮、额度。
2. “识别设置”：类别、地区、观测地点、观测时间、低置信度阈值（默认 80%）、近似并列差值（默认 10 个百分点）、结果等待时长（默认 60 秒）。观测信息均为必填 QLineEdit，运行期间禁用并保存到 QSettings。
3. “目录设置”：源目录、目标目录、浏览按钮。
4. “任务”：开始、停止、进度条、计数，计数包含人工复核与暂不分类。
5. “日志”：只读多行文本，支持复制错误摘要。

两个阈值使用 QDoubleSpinBox 或等价数值控件，范围 0～100，小数位与显示精度统一；运行期间只读。结果等待时长使用 QSpinBox，范围 1～600 秒。以上数值均保存到 QSettings，不保存界面“%”或“秒”后缀。

### 13.2 线程通信

建议 Worker 信号：

- `quota_updated(Quota)`。
- `scan_completed(total, skipped, resume_review, resume_copy)`。
- `progress_changed(current, total)`。
- `file_started(relative_path)`。
- `review_requested(request_id, review_context)`。
- `file_finished(relative_path, status, message)`。
- `log_message(level, message)`。
- `batch_finished(summary)`。
- `fatal_error(message)`。

`review_context` 包含图片路径、去重候选、复核原因、两个阈值、最高置信度和前两名差值。Worker 发出请求前必须完成 review_pending 落盘，然后等待唯一 request_id 对应的线程安全结果；主线程创建并执行 QDialog，再通过 `resolve_review(request_id, ReviewResult)` 返回答复。答复类型为：

- `CONFIRM`：含用户选中的物种 ID 和动物类别。
- `CUSTOM`：含人工确认的鸟种中文名，按该名称归档当前目标。
- `DEFER`：仅推迟当前 target_index，保留 review_pending，继续同一图片的下一个未确认目标。
- `STOP`：保留 review_pending，停止整批。

禁止在 Worker 线程直接创建 QDialog，也禁止用轮询 UI 变量的忙等待。等待期间只阻塞分类 Worker，主线程保持可响应；每个 request_id 只能完成一次，Worker 退出前清理等待项。主窗口关闭时按 DEFER + STOP 处理并等待 Worker，不允许留下悬挂线程。

### 13.3 人工复核弹窗

新增 `ReviewDialog`，只在主线程使用：

- 上方显示触发原因、实际最高置信度和前两名差值。
- 图片区使用 QImageReader/QPixmap 按可用区域缩放，保持宽高比；避免无必要地解码到超过预览所需的巨大像素缓冲。显示源相对路径。
- 高亮框使用归一化 API 坐标映射到预览；Retina/高 DPI 下必须通过 `QPixmap.deviceIndependentSize()` 获取逻辑尺寸，不能把物理像素宽度直接用于 QPainter 坐标或居中留白计算。图片标签自身发出 resize 信号时必须重新计算预览与检测框，不能只监听整个弹窗的 resize，否则分割器或初始布局改变标签宽度后会漏算横向留白。
- 候选区使用单选列表和滚动容器，展示全部去重候选的中文名、英文名、拉丁名与 `confidence_percent`，百分比保留统一小数位。列表开启自动换行，并为每项预留中文名与英文/拉丁名的两行高度，避免长名称被省略号截断；没有英文名和拉丁名的候选只占一行。
- 默认选中第一候选，确认时按物种 ID + 动物类别回查候选，不用显示名称作为唯一键。
- 候选列表下方提供“人工确认鸟名”输入框和“按人工鸟名归档”按钮：空白或仅含空白字符时按钮禁用，提交时去除首尾空白并返回 CUSTOM；人工名称不会改写候选列表，输入框回车与按钮点击等效。
- 按钮为“确认所选鸟种”“按人工鸟名归档”“稍后处理（仅当前目标）”“停止本批次”；窗口关闭按 STOP 安全停止。DEFER 仅推迟当前目标并继续后续目标，已确定物种部分归档；STOP 才结束整批。
- 预览加载失败时显示错误占位和路径，但保留候选、人工鸟名输入与各决定按钮；绝不回退为自动选择。
- 弹窗无自动超时，避免用户不在电脑旁时默认确认错误物种。

### 13.4 系统浅色／深色外观

`app.main()` 在创建主窗口前调用 `install_system_theme(app)`。`SystemThemeController` 以 QApplication 为父对象，初始化时根据当前 `QApplication.palette()` 生成应用级样式，并监听 `QStyleHints.colorSchemeChanged`；系统外观变化时重新读取调色板并刷新样式，无需重启。

自定义颜色只允许通过 `application_stylesheet(palette)` 从 `Window`、`WindowText`、`Text`、`Base`、`AlternateBase`、`Mid`、`Highlight` 和 `HighlightedText` 等角色派生。主窗口不再单独设置固定浅色样式；下拉弹出列表、候选列表和日志与输入控件使用同一调色板。复核图片预览保留深色图片底板和 `#ffb020` 检测框，局部占位文字颜色不被应用样式覆盖。

主题测试使用已知浅色／深色调色板验证颜色进入样式及 WCAG 对比度，并通过发出 `colorSchemeChanged` 验证运行时刷新；另用 `QT_QPA_PLATFORM=offscreen` 截图检查实际控件渲染，不修改真实 macOS 外观。

### 13.5 设置与 Key

QSettings 可保存非敏感字段，包括两个复核阈值和结果等待时长。API Key 不调用 QSettings.setValue。日志统一经过 `redact_secret(text, api_key)`，同时避免 requests 异常打印完整请求头。

## 14. 日志与诊断

当前至少保留 UI 日志，并允许控制台输出脱敏诊断。若增加文件日志，放在用户可写的应用数据目录而非源目录或 birdclass 包目录，并使用 RotatingFileHandler 限制大小。

建议级别：

- INFO：开始、扫描汇总、完成摘要。
- WARNING：单图校验/识别失败、用户停止。
- ERROR：Key、网络、CSV、磁盘等致命问题。

诊断信息包括软件版本、resultid、相对路径、业务码；不包含 Key、Authorization、完整图片二进制。

## 15. 测试策略

### 15.1 单元测试

**API 解析**

- 普通/无限额度。
- 非 200、非 JSON、空数组、未知字段。
- 上传成功与全部已知业务码。
- 用假时钟验证轮询 1001 到 1000，以及到达可配置总等待截止时间后超时。
- 多目标、多空 list、并列置信度、名称分隔符缺失。

**扫描**

- 大小写扩展名、子目录、非图片。
- output 位于 source 内时剪枝。
- 相同目录、反向嵌套、符号链接循环。

**上传准备与压缩**

- 2,000,000 字节边界：未超限不创建文件，超限才创建临时 JPEG。
- 用确定性高熵测试图片验证质量递减；构造质量压缩仍超限的图片验证等比例缩放。
- 每次上传结果均满足字节数和 11～8192 尺寸；最小边无法继续缩放时受控失败。
- RGB、RGBA、LA、透明 PNG 和 EXIF 方向；透明区域白底，原图字节、尺寸、mtime 不变。
- cleanup 在成功和每种异常后调用且幂等；Windows 句柄关闭后可删除。
- FileArchiver 只收到 original_path，归档前后的像素摘要一致；候选预览也使用 original_path。
- CSV 的 upload_was_compressed/upload_bytes 正确，恢复 review_pending 不访问已删除临时图。

**CSV**

- 中文和逗号转义、BOM。
- completed 跳过、文件身份变化重识别。
- recognized 续拷、failed 重试。
- review_pending 的 candidate_payload 完整恢复，损坏 JSON 被拒绝。
- 多事件取最后状态、坏表头、未来 schema、末尾损坏。
- v3 观测信息往返；v1/v2 表头读取、追加前迁移和对应版本备份。
- 写失败后批次停止。

**候选复核决策**

- 最高值低于 80 触发；恰好 80 不触发低置信度。
- 前两名差值恰好 10 触发；大于 10 不触发近似并列。
- 单候选高置信度自动通过，单候选低置信度必须复核。
- 同物种仅在当前框内先去重，跨框候选不得制造虚假的第二名；最终归档再跨框去重。
- 两个原因同时满足时均返回；自动和手动选择均保留正确 selection_mode。
- Decimal 边界、0/100 阈值、非法负数和超过 100 的配置。
- confidence_raw 到 confidence_percent 的显式适配测试，单位以真实联调结果为准。
- CUSTOM 候选构造：manual ID、动物类别继承、source_order=-1、confidence_raw=manual、数值置信度 0；空白名称与空候选受控失败。

**归档**

- Windows 非法字符和保留名。
- 同名同内容、同名不同内容。
- 中文路径、长名称、临时复制失败清理。
- 观测地点/时间非法字符清理；同前缀连续编号、不同前缀独立编号、跨扩展名连续；多鸟复制件共享观测信息。
- UI 修改观测信息后恢复旧任务，仍使用事件中的原观测信息。
- 人工鸟名归档：目录与文件名、原图/复制件元数据、CSV manual 字段；同图同名去重。

**额度**

- 0、N>R、N≤R、无限。
- 受理即扣本地名额。
- recognized 续拷、review_pending 恢复复核均不占额度。
- 用户停止后不再上传。

### 15.2 集成测试

使用 fake DongNiaoClient 或 HTTP mock，不访问真实服务，串联：

1. 扫描 → 识别 → 复制 → CSV。
2. 识别成功后模拟复制失败，第二次运行不调用上传而完成复制。
3. 完成一部分后额度停止，第二次运行跳过 completed。
4. 输出在源目录内，第二次扫描不会处理输出图片。
5. 低置信度/近似并列 → review_pending → 人工选择第二候选 → 正确目录 → completed。
6. 多目标中推迟一个目标后继续复核其他目标，已确定物种部分归档；重启只恢复未确认目标，不上传、不重复复制，额度 0 仍可确认归档。
7. Worker 停止、弹窗等待期间关闭窗口，无悬挂线程或重复 request_id 完成。
8. 超限原图 → 临时压缩上传 → 删除临时图 → 原图归档；分别在成功、识别失败、超时和人工复核路径验证。
9. 人工鸟名归档；多个目标同名只复制一次；与 DEFER 混用后恢复不重新上传、不重复复制；schema 1 旧记录同样可人工归档。

### 15.3 UI 测试

pytest-qt 验证按钮状态、额度显示、错误对话框、日志脱敏、停止按钮。ReviewDialog 验证图片比例、候选及百分比、候选两行行高与自动换行、人工鸟名空白禁用与去空白提交、默认选中、选择非首项、DEFER/STOP/关闭映射、长候选滚动和预览失败占位。主题测试验证浅色／深色调色板颜色、至少 4.5:1 的文字背景对比度、主窗口无局部固定浅色样式，以及 `colorSchemeChanged` 触发应用样式刷新。UI 测试不依赖真实磁盘大图库。

2026-10-24 联调结果：

## 19. 设计自检结论

- 无依赖未决问题才能开始的核心占位；默认决策已明确。
- 额度停止与断点续跑使用同一批次模型，不冲突。
- review_pending / recognized / completed / failed 状态覆盖待人工复核、识别成功但复制失败及正常完成情况。
- 低置信度与近似并列采用明确的包含边界规则；候选先去重再比较，人工选择可追溯。
- 复核弹窗仅在主线程创建，Worker 等待有唯一请求标识和取消语义，不会冻结 UI。
- 超限图的 upload_path 与 original_path 明确分离；临时图有大小/尺寸验证和完整清理路径，预览及归档始终使用原图。
- 上传响应丢失的重复扣费窗口已明确披露，没有作绝对保证。
- 地区快照、多目标选择、同名冲突、输出嵌套和 Windows 命名均有可测试规则。
- 范围适合一个实现计划，无需拆成多个独立项目。
