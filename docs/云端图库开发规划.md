# 羽栖云端图库开发规划

- 版本：0.1
- 日期：2026-11-05
- 状态：规划稿，未开始实现
- 当前桌面版本：0.1.4
- 当前自动化测试：241 项通过

## 1. 背景

羽栖目前是本地优先的 macOS 桌面工具：

- 照片保存在本地归档目录
- `.birdroost/groups/*.json` 是业务真相
- `.birdroost/index.sqlite` 是浏览器缓存
- IOC 15.2 名录、中文别名、地点层级、人工复核和纠错都在本地完成
- 当前图库约 1336 张图片、1189 张非特殊图片、277 种鸟、1155 个 group（2026-11-05 实测）

下一阶段希望把图库扩展到云端，使不同设备甚至手机可以：

1. 登录账户
2. 先看到缩略图目录
3. 按需下载原图
4. 未来支持云端纠错、同步和分享

## 2. 目标与非目标

### 目标

- 原图和缩略图有可靠的云端副本
- 客户端不需要一次下载完整图库
- 同一账户可在 Mac、Web、手机等多端访问
- 云端元数据能表达现有的 group、目标、副本、观测信息和纠错记录
- 上传/下载可恢复、可校验、不重复
- 云端权限严格按用户隔离
- 保留本地优先：断网时仍可使用本地图库

### 非目标（第一阶段不做）

- 不做多人协作编辑
- 不做公开图库/社区
- 不做手机端完整修图
- 不把现有 PySide6 UI 直接搬到手机
- 不一开始就做复杂的端到端加密
- 不替换本地 `.birdroost` 作为唯一真相

## 3. 产品原则

1. **本地优先**：云端是备份、同步和远程访问层，不是本地不可用的替代品。
2. **原图不可变**：云端原图按内容哈希存储，不因纠错、改名而改变 bytes。
3. **元数据可编辑**：观测地、时间、物种、纠错记录可以变，保留 revision。
4. **缩略图优先**：列表和手机端只看缩略图，原图按需下载。
5. **账户即租户**：所有数据按 `user_id` 隔离，客户端不能直接持有 COS 永久密钥。
6. **可迁移**：云端导出应能重建本地库；不把业务真相锁在某个云厂商的私有格式里。
7. **隐私优先**：鸟点位置可能敏感，默认不公开精确地点。

## 4. 阶段规划

### 阶段 0：基础准备（约 1～2 周）

**目标**：为云端化准备稳定 ID、哈希和导出格式。

任务：

- 给每张原图计算 SHA-256
- 统一 `photo_id` / `group_id` / `copy_id`
- 定义云端元数据 JSON schema
- 提供本地图库导出清单
- 生成缩略图（512px WebP）
- 设计 COS 对象命名和用户隔离规则

验收：

- 同一张原图的不同物种副本只对应一个 `sha256`
- 导出清单包含 group、target、copy、observation、correction
- 缩略图可以从原图稳定重建
- 本地图库不因导出而改变

### M0 执行进展（2026-11-05）

已完成本地导出原型：

```bash
PYTHONPATH=src .venv/bin/python -m birdclass.cloud_export \
  --archive /Users/zjq/LR_workspace/鸟 \
  --output /Users/zjq/LR_workspace/鸟-cloud-export
```

输出：

```text
manifest.json
thumbs/{sha256}_256.webp
thumbs/{sha256}_512.webp
originals/            # 当前 M0 不复制原图，留空占位
```

实测：

- 1241 张唯一原图
- 1252 个 copy
- 1140 个含图片的 group
- 2482 张缩略图
- 13 个已失效的待复核路径记录

说明：

- M0 只做本地清单和缩略图，不访问云、不修改本地图库
- 原图不复制到导出目录，manifest 通过 `source_root + local_relative_path` 指回本地文件
- 相同 SHA-256 的多个物种副本只生成一组缩略图
- 失效路径需要后续做一次 group 清理

### 阶段 1：单用户云备份（约 2～3 周）

**目标**：先把图库安全地上云，不做账户系统。

任务：

- 创建私有 COS 桶
- 上传原图、缩略图和元数据清单
- 上传前校验 SHA-256
- 失败重试、断点续传
- 云端目录浏览和手工恢复
- 导出校验报告

验收：

- 随机抽取 50 张照片，下载后 SHA-256 一致
- 中断上传后可继续
- 不产生重复原图对象
- 本地库不受影响
- 云端不可公开访问

### 阶段 2：账户与只读多端（约 3～4 周）

**目标**：登录后在其他设备/手机查看缩略图和按需下载原图。

任务：

- 账户登录（优先 CloudBase Auth 或等价服务）
- 设备注册和退出登录
- 后端签发 COS 临时凭证/签名 URL
- 照片列表、缩略图、按需原图 API
- Web/PWA 只读端
- 手机端先做响应式 Web，不直接移植 PySide6

验收：

- 账户 A 无法访问账户 B 的对象
- 手机首屏只拉缩略图，不下载原图
- 点开大图才请求原图
- 退出登录后本地缓存策略明确
- 账号注销/导出路径明确

### 阶段 3：双向同步（约 4～6 周）

**目标**：多设备可以修改观测信息、纠错和删除。

任务：

- 本地变更日志
- 云端 change feed
- 增量推送/拉取
- 软删除 tombstone
- 冲突检测和解决策略
- 离线编辑队列
- 同步状态 UI
- 纠错历史保留

验收：

- 两台设备离线修改同一张照片，重新联网后能看到冲突提示或按策略合并
- 删除不会在另一台设备“复活”
- 重复上传不产生重复记录
- 同步失败可重试且不丢数据

### 阶段 4：移动端编辑与分享（后续）

- 手机端纠错
- 分享卡片
- 行程/年度清单
- 社交分享
- 可选公开图库

## 5. 里程碑与交付物

| 里程碑 | 主要交付 | 依赖 |
|---|---|---|
| M0 | 哈希、稳定 ID、导出 schema、缩略图 | 无 |
| M1 | COS 私有桶、单用户备份/恢复 | M0 |
| M2 | 账户、只读 Web/PWA、按需下载 | M1 |
| M3 | 双向同步、冲突处理、离线队列 | M2 |
| M4 | 移动端编辑、分享 | M3 |

## 6. 现有数据迁移

1. 扫描本地 `.birdroost` 和图片目录
2. 对每个 copy 计算 SHA-256
3. 相同哈希只上传一个原图对象
4. 为每个 copy 建元数据链接（不复制 bytes）
5. 生成 512px/256px 缩略图
6. 上传元数据清单
7. 校验：
   - 本地 copy 数
   - 云端唯一原图数
   - 元数据 copy 数
   - 随机抽样哈希
8. 保留本地库，不立即切换为云端真相

迁移注意：

- 同一张原图可能对应多个物种目录，不能按目录重复上传
- 文件名不是身份，`sha256` 才是
- `legacy_location` / `legacy_time` 保留
- 纠错记录单独迁移
- 迁移失败可回滚，不删除本地

## 7. 成本与配额

主要成本：

- COS 原图存储
- 缩略图存储
- 请求次数
- 手机端下行流量
- 数据库/函数/队列
- 跨地域流量

建议：

- 默认私有桶 + 生命周期策略
- 缩略图优先
- 原图短时效签名 URL
- 每月预算告警
- 免费/付费账户设置配额
- 公开分享单独计量

## 8. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 账户系统范围膨胀 | 延期 | 先做单用户备份，再做账户 |
| 同步冲突复杂 | 数据错乱 | 先只读，后双向；字段级冲突策略 |
| 手机端是另一套客户端 | 成本高 | 先 Web/PWA，API-first |
| 云端锁定 | 迁移困难 | 元数据可导出，对象用标准格式 |
| 隐私/合规 | 鸟点泄露 | 私有桶、模糊位置、注销/导出 |
| 流量费用 | 成本不可控 | 缩略图优先、配额、告警 |
| 原始 API Key 泄露 | 账户风险 | Keychain/加密保存，后端不记录明文 |

## 9. 暂不决定的问题

1. 只服务自己，还是未来开放给其他用户？
2. 后端用腾讯云 CloudBase，还是自建 FastAPI/Go 服务？
3. 手机端先做 PWA，还是直接做原生 iOS/Android？
4. 是否需要端到端加密？会牺牲服务端搜索和缩略图生成。
5. 云端是否保存懂鸟 API Key？如果保存，如何加密和隔离？
6. 免费额度、付费方案和存储配额？
7. 是否需要共享图库/朋友协作？

## 10. 推荐顺序

```text
M0 稳定 ID/哈希/缩略图
→ M1 单用户云备份
→ M2 账户 + 只读 Web/PWA
→ M3 双向同步
→ M4 移动编辑/分享
```

不要从“账户系统 + 多端同步 + 手机 App”同时开始。先用 M1 验证云存储、缩略图和成本，再决定是否值得做完整账户体系。
