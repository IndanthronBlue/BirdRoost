# 羽栖 Key-only 云端图库开发规划

- 版本：1.0
- 日期：2026-11-05
- 状态：正式规划
- 当前桌面版本：0.2.0
- 当前自动化测试：250 项通过

## 0. 结论

采用 **Key-only 单用户模式**：

```text
分类：懂鸟 API Key
图库：腾讯云 COS 配置
```

不建设账户系统，不建设后端服务，不做云端权限系统。

COS 前缀 `users/<prefix>/` 只作为**图库命名空间**，不是安全边界。这个模型适合个人、可信设备、单人或家庭使用；如果未来要开放给多个用户，必须改成“每用户独立桶/密钥”或补后端。

## 1. 产品模型

### 1.1 两个 Key

| Key | 用途 | 保存位置 |
|---|---|---|
| 懂鸟 API Key | 图片识别 | macOS 钥匙串 |
| COS SecretId/SecretKey | 图库读写 | 桌面钥匙串；手机只读 Key |

### 1.2 图库身份

```text
Bucket + Region + Endpoint(可选) + Prefix
```

`Prefix` 是图库/用户标签，例如：

```text
users/zjq/
```

进入新电脑或手机时，填入同一组 COS 配置和前缀，即可看到同一图库。

### 1.3 设备角色

| 设备 | 能力 |
|---|---|
| 桌面 PC | 分类、浏览、纠错、删除、上传、下载 |
| 手机 | 只读浏览、缩略图、按需下载原图到相册 |

手机端不写回云端，避免第一版引入双向冲突。

## 2. 用户流程

### 2.1 某次观鸟后的分类

```text
修好图 → 放到待分类目录
→ 启动归档工具
→ 填懂鸟 API Key
→ 选择观测国家/地区/地点/时间
→ 批量分类到本地图库
→ 删除或保留待分类目录
```

要求：

- 待分类目录和本地图库目录分离
- 分类后保留本地图库副本
- 待分类目录删除不影响图库
- 未修完的图可留在待分类目录下次继续

### 2.2 PC 浏览与上传

```text
打开归档浏览
→ 本地浏览/筛选/纠错
→ 批次完成后询问是否上传新内容
→ 上传原图 + 缩略图 + manifest
```

要求：

- 手动“云备份”入口保留
- 每次新批次完成后自动询问
- 默认只上传新增/变化内容
- 已存在对象跳过
- 上传可取消、可重试

### 2.3 新电脑首次使用

```text
安装 App
→ 填 COS Bucket / Region / Endpoint / Prefix / Secret
→ 读取云端 manifest
→ 选择：
   A. 下载完整图库
   B. 只下载缩略图和元数据
→ 浏览/按需下载
```

第一版桌面端建议优先实现 **A 完整图库下载**。

原因：

- 当前桌面浏览器只认本地图片文件
- 缩略图模式需要把 `ArchiveIndex` 改成“远端条目 + 本地缓存”
- 完整下载能最快形成闭环

桌面缩略图模式放到 P2。

### 2.4 纠错与删除

```text
PC 纠错/删除
→ 本地 group 标记 dirty
→ 更新 manifest revision
→ 上传 manifest
→ 其他设备看到新 revision
```

删除策略：

- 不立即删除 COS 原图
- manifest 中写 `deleted_at` / tombstone
- 手机和其他 PC 隐藏
- 经过保留期后再清理对象

### 2.5 手机端

```text
安装手机 App
→ 填 COS 配置（只读 Key）
→ 下载 manifest + 名录/大纲
→ 默认下载缩略图
→ 点开大图时下载原图
→ 保存到手机相册
```

手机端：

- 不连接业务后端
- 不写回云端
- 不纠正分类
- 不删除云端内容
- 只读 Key，禁止 Put/Delete

## 5. 架构

```text
┌────────────────────┐
│ macOS App           │
│ 本地图库 + SQLite   │
└─────────┬──────────┘
          │ COS SDK（用户自己的 Key）
          ▼
┌────────────────────┐
│ 腾讯云 COS 私有桶   │
│ manifest            │
│ originals           │
│ thumbs              │
└─────────▲──────────┘
          │ COS SDK（只读 Key）
┌─────────┴──────────┐
│ 手机 App            │
│ manifest + 缩略图   │
│ 按需原图            │
└────────────────────┘
```

没有后端、没有账户服务。所有权限由 COS 子账号和桶策略控制。

## 6. 云端数据契约

### 6.1 对象布局

```text
users/<prefix>/manifest.json
users/<prefix>/originals/<sha256>.<ext>
users/<prefix>/thumbs/<sha256>_256.webp
users/<prefix>/thumbs/<sha256>_512.webp
users/<prefix>/taxonomy/<version>.json
```

### 6.2 manifest v2

```json
{
  "schema_version": 2,
  "library_id": "uuid",
  "prefix": "zjq",
  "revision": 12,
  "device_id": "mac-mini",
  "updated_at": "2026-11-05T...",
  "taxonomy_version": "IOC 15.2",
  "counts": {},
  "photos": [],
  "groups": [],
  "copies": [],
  "tombstones": []
}
```

要求：

- `revision` 每次写入递增
- `device_id` 标识最后写入设备
- 上传前先读取远端 revision
- 远端 revision 大于本地已知 revision 时提示冲突
- tombstone 不立即删除原图

### 6.3 原图

- 内容寻址：`sha256`
- 多物种副本共享同一个原图对象
- 文件名不参与云端身份
- 上传前校验 SHA-256
- 上传后 HEAD 校验大小

### 6.4 缩略图

- 256px WebP：列表
- 512px WebP：详情/手机
- 按 EXIF 方向矫正
- 不绘制检测框
- 缺失时可按需重建

## 8. 里程碑

### M1.1 自动上传闭环（约 1～2 周）

交付：

- 批次完成信号
- 新 group 检测
- 自动询问弹窗
- 后台增量导出/上传
- 上传结果提示

验收：

- 分类 10 张新图，完成后弹窗
- 确认后只上传新增对象
- 取消不影响本地
- 重复上传不会产生重复对象

### M1.2 manifest v2（约 1～2 周）

交付：

- revision/device_id/tombstone
- manifest 上传前版本检查
- 冲突提示
- 删除不立即删原图

验收：

- 两台设备修改同一 group 有冲突提示
- 删除后另一台设备隐藏
- 原图不会被误删

### M1.3 新电脑完整恢复（约 2～3 周）

交付：

- 云图库配置页
- 下载 manifest
- 下载全部原图和缩略图
- 重建 `.birdroost` 和 SQLite
- SHA-256 校验

验收：

- 新电脑只填 COS 配置即可浏览完整图库
- 抽样图片哈希一致
- 断点续传可用
- 下载中断可恢复

### P1 纠错/删除同步（约 2～4 周）

交付：

- dirty queue
- manifest 自动上传
- tombstone
- 冲突处理

### P2 手机只读 App（约 6～10 周）

交付：

- iOS 或 Android 只读客户端
- COS 只读 Key
- manifest/名录/缩略图
- 按需原图
- 保存到系统相册

验收：

- 手机只填 COS 配置即可浏览
- 首屏不下载原图
- 点开才下载原图
- 保存到相册成功
- 手机 Key 无写权限

## 9. 关键技术决策

1. **不做后端**：客户端直接使用 COS SDK。
2. **桌面优先完整下载**：先闭环，再做缩略图模式。
3. **手机只读**：不做手机上传/纠错。
4. **Prefix 不是权限**：只为组织对象，安全依赖 COS 子账号和桶策略。
5. **删除用 tombstone**：保留恢复能力。
6. **原图内容寻址**：多物种副本不重复 bytes。
7. **manifest 是目录**：不依赖 COS ListObjects 做业务查询。
8. **Secret 存 Keychain**：桌面和手机都使用系统安全存储。

## 10. 安全与风险

### 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| COS Key 泄露 | 手机/电脑可读整个允许范围 | 私有桶、只读子账号、Keychain、轮换 |
| Prefix 不是权限 | 知道 Key 就能访问允许对象 | 个人使用可接受；多人必须分桶/分 Key |
| 多设备冲突 | 两个 PC 同时改 manifest | revision 检查 + 冲突提示 |
| 手机保存相册格式 | WebP 兼容性 | 下载原图或转 JPEG |
| 流量成本 | 手机下载原图 | 缩略图优先、按需下载、配额 |
| 云端误删 | 删除同步 | tombstone + 保留期 |
| 大图库 manifest 变大 | 手机下载慢 | gzip、分页、taxonomy 单独对象 |

### 安全要求

- COS 桶必须私有
- 手机使用只读子账号
- Secret 不写入 manifest、日志、QSettings
- Secret 存 macOS Keychain / iOS Keychain / Android Keystore
- 手机端只允许 GetObject/HeadObject
- 分享/多人使用前重新评估权限模型

## 11. 成本

主要成本：

- 原图存储
- 缩略图存储
- 上传/下载请求
- 手机下行流量
- 多设备重复下载

控制：

- 内容哈希去重
- 缩略图优先
- 上传跳过已存在
- 手机缓存
- COS 生命周期策略
- 预算告警
